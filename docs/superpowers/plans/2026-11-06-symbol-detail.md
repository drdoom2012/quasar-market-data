# Symbol detail page — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Draw the detail view that the dashboard's symbol links point to (`#/symbol/<symbol>?venue=&timeframe=`): header, status card, three KPI cards, three stacked charts with a range switch, history coverage and quality checks, from data the API really has and with no change to the API.

**Architecture:** The tool gets a new read-only route `/detail.json` (a pure core `detail.py` + `detail_validate.py`, an orchestrator `detail_refresh.py` with a small cache, wired into `server.py`) that pages the API's candles, open interest rows and funding rows for one series and returns one validated document. The page gets a second classic script `detail.js` (pure functions above `// --- DOM below ---`, tested under Node, then the DOM and the charts) and a hash router. Charts are drawn by the vendored `lightweight-charts` 5.2.1 (one file, no build step, no CDN). State, reasons, history start and coverage come from the existing `/overview.json` (plus two additive fields); the detail view judges nothing itself.

**Tech Stack:** Python 3.12 standard library only for the tool (`decimal`, `re` added to the boundary allowlist), plain JavaScript, `lightweight-charts` 5.2.1 (Apache-2.0, vendored), pytest + Node.js (16.13 here), ruff, mypy.

**Spec:** `docs/superpowers/specs/2026-11-06-symbol-detail-design.md` (APPROVED 2026-11-06). Contract references "C§x" are to `docs/contracts/api-v1.md`.

## Review Focus

Each line is pinned by a test in the task named.

1. A missing slot is a gap, never an interpolated segment (whitespace points on the 5-minute grid) — Task 7 (`denseSeries`, `candleBars`, `oiPoints`).
2. One failed page of a 30-day read makes that whole part an error, never a half-drawn series; the other parts still show — Task 4.
3. Exact decimals: a change of `"0.1"` to `"0.3"` is `+200.00`, never float noise; a zero old value is `n/a`; a rounding to zero has no sign — Task 3.
4. An unknown or repeated query parameter, an unknown range, a bad `%XX` escape, or an unsupported venue/timeframe is refused before any API call; a series the API does not list is refused after the two head calls and before any part call — Task 4 and 5.
5. A response that arrives after the user went to another symbol or range must never be drawn; an overview error after a render must clear the detail; `detail.js` arriving after the first snapshot must still draw it — Task 7 (`createDetailLoader`, `detailViewState`) and Task 8.
6. Symbol names with `/`, `:`, `&`, `#` or spaces round-trip through the route; a name that cannot be encoded (a lone surrogate) gives the link `#`, never a wrong series; a bookmarked URL waits for the snapshot — Task 7 (`parseRoute`, `detailViewState`).
7. A Regular and a Special funding row in the same second are not silently merged — Task 7 (`fundingPoints`).
8. Funding points older than the shown range must not distort the shared time axis — Task 4 (`rows` hold only the shown window) and Task 7.
9. A stale or stopped series must not look current: the age is shown from the API's clock, and a range with no rows says "no data in this range (newest stored: …)" — Task 7 (`kpiModel`).

  - `@dataclass(frozen=True) class DetailWindows: shown: Window; candles: Window; open_interest: Window; funding: FundingWindow`
  - `detail_windows(as_of_ms: int, range_name: str) -> DetailWindows`: `E = (as_of_ms // TF_MS + 1) * TF_MS`, `S = E - RANGE_SLOTS[range_name] * TF_MS`; `shown = Window(S, E)`; `candles = Window(S - TF_MS, E)` (one lookback slot); `open_interest = Window(S + TF_MS - OI_REFERENCE_SLOTS * TF_MS, E + TF_MS)` (one hour of lookback; rows with `time_ms >= S + TF_MS` are the shown ones); `funding = FundingWindow(min(S, E - FUNDING_MIN_SLOTS * TF_MS), as_of_ms)` (closed, explicit end). `ValueError` for an unknown range or any bound outside `[MIN_TS_MS, MAX_TS_MS]` or `as_of_ms` not an `int`.
  - `percent_change(new: str, old: str) -> str | None`: `Decimal` arithmetic, `q = ((new - old) / old * 100).quantize(Decimal("0.01"), ROUND_HALF_EVEN)`, the whole computation including `quantize` inside one `try/except InvalidOperation` (also `DivisionByZero`); `None` when `old` is zero, either is not a finite decimal string; text `"+0.84"`, `"-1.20"`; the sign is decided by `q`, not by the text: `q == 0` prints `"0.00"` with no sign.
  - `candle_change(rows: Sequence[CandleRow]) -> dict[str, str] | None`: `{"percent": ..., "previous_close": ...}` for the last row against the row exactly one slot earlier, else `None`. `rows` include the lookback row.
  - `open_interest_change(rows: Sequence[OiRow]) -> dict[str, object] | None`: the last row's `value` against the row with `t == last.t - OI_REFERENCE_SLOTS * TF_MS`: `{"percent": ..., "reference_ms": int}`, else `None`.
  - `part_ok(**fields: object) -> dict[str, object]` (`{"status": "ok", "code": "", "detail": "", **fields}`), `part_empty()` (`status "empty"`), `part_disabled()` (`status "disabled"`), `part_error(invalid: Invalid) -> dict[str, object]` (`status "error"`, `code`, `detail` from the `Invalid`).

### Task 4: Page validators and the `Detailer`

**Files:**

- Test: `tests/tools/symbol_overview/test_detail_validate.py`, `tests/tools/symbol_overview/test_detail_refresh.py`

**Interfaces (4a, `detail_validate.py`; consumes `_decode`, `_bad`, `_ts`, `_aligned_ts`, `_non_negative`, `_all_or_none_ts` from `validate.py` — import the private names as they are; no refactor of `validate.py`; row types from `model.py`):**
  - `@dataclass(frozen=True, slots=True) class CandlePage: rows: tuple[CandleRow, ...]; next: int | None; oldest_ms: int; newest_ms: int`; `OiPage` (same shape with `OiRow`); `FundingPage: rows: tuple[FundingRow, ...]; next: int | None; window_state: str; conflicted_events: int; complete: bool`.
  - `candle_page_result(status: int, content_type: str | None, body: bytes, *, instrument: InstrumentRow, start: int, end: int) -> CandlePage | Invalid`; `open_interest_page_result(...)` and `funding_page_result(...)` with the same parameters. Checks (each failure is `Invalid`, codes from `INVALID_CODES`; add none; `schema` is the code for "page does not advance" and "too many pages" too): decode via `_decode`; echo of `venue`, `symbol`, `timeframe`/`period` and `start`/`end` (`echo`) and of `time_semantics` (`"period_end"` for open interest, `"settlement"` for funding; candles have none); `series` block present: candles `oldest_open_time_ms`/`newest_open_time_ms` aligned and valid, open interest `oldest_time_ms`/`newest_time_ms` aligned, funding `oldest_funding_time_ms`/`newest_funding_time_ms` **both null or both valid timestamps, not aligned** (`_all_or_none_ts`); `next` key **present** (a missing key is `schema`); every integer is `type(x) is int` (`True` is refused); rows ascending and inside the window (candles/OI `[start, end)`, times aligned; funding `[start, end]`, no alignment); candle/OI rows unique by `t`; funding rows ordered by `(t, rate_type)` with `Regular` before `Special`, unique by the pair, and **across pages `t` strictly increases** (C§6.7.3: a page never splits one `funding_time_ms`); the first row is `>= start` of that page (the cursor); every decimal field passes the decimal rule of the Global Constraints (`-` allowed only for `funding_rate`; `mark_price` and candle/OI values non-negative), `conflicted` is `bool`, `turnover`/`mark_price` are `None` or decimal strings; `next` is `None` or an `int` greater than the last row and `< end` for candles and open interest, `<= end` for funding (C§6.7.3); **a page with no rows and a non-null `next` is `schema`**; candle sanity via `Decimal`: `low <= min(open, close)`, `high >= max(open, close)`, `volume >= 0`; funding `coverage` has `window_state` in `FUNDING_WINDOW_STATES`, non-negative `conflicted_events`, bool `complete` (validated, not output). A `404` with `api_error` `unknown_series` is returned as `Invalid("api_error", "unknown_series")` by `_decode` (the caller decides what it means).

**Interfaces (4b, `detail_refresh.py`; consumes everything above, `Fetch`, `RawResponse`, `TransportError`, `health_result`, `instruments_result`, `open_interest_health`, `funding_health` (they take the raw `/health/ingest` response — keep `health_raw` — and the validated `Health`), `page_error`):**
  - `@dataclass(frozen=True, slots=True) class DetailAnswer: status: int; body: bytes` (the JSON, UTF-8, already encoded: the cache holds bytes, not dicts).
  - `class Detailer: __init__(self, fetch: Fetch, *, deadline_s: float = 30.0, wait_s: float = 45.0, cache_bytes: int = 16 * 1024 * 1024, monotonic: Callable[[], float] = time.monotonic) -> None` and `get(self, symbol: str, venue: str, timeframe: str, range_name: str) -> DetailAnswer`.
  - Behaviour: first `venue != VENUE` or `timeframe != TIMEFRAME` → `DetailAnswer(404, …"unsupported_series")` with **no** call at all. Cache hit (key = the four arguments, lifetime `RANGE_TTL_S[range_name]`; successful `200` answers only, in an LRU bounded by the **total bytes** `cache_bytes`, an answer larger than the budget is served but not kept) → return it. Failures and 404s are kept 5 s in a separate small dict (at most 64 keys). Otherwise take one lock (one detail refresh at a time; cached answers do not take it) with `acquire(timeout=wait_s)`; not acquired → `DetailAnswer(503, …"busy")`; **after** taking the lock look in the cache again.
