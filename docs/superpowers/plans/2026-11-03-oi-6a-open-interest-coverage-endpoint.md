# OI-6a Open Interest Coverage Endpoint Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `GET /v1/open-interest/coverage` (counts and runs of open interest slots for a window of at most 10 000 slots), its contract text, and the benchmark harness that measures a refresh of the symbol overview at 300 and 600 symbols (issue #6, first of its two slices).

**Architecture:** The new endpoint is a read-only sibling of `GET /v1/coverage`: a pure domain function groups the existing `open_interest_slot_states` sequence into runs and counts, a reader reads only `time_ms` of rows and conflict records in one read transaction, the handler follows the order of checks of `GET /v1/open-interest`. The harness drives a real `quasar-api` process over HTTP with the call pattern of the overview tool. No schema change, no configuration key, no change to any existing endpoint.

**Tech Stack:** Python, FastAPI/Starlette, SQLite WAL, pytest, `uv`, `make`.

**Spec:** `docs/superpowers/specs/2026-11-03-oi-6-open-interest-overview-design.md` (APPROVED 2026-11-03, U2 = C). Sections 5, 6, 7 and 10 are the ones this plan implements; the OI-6b page (section 8) is **not** in this plan and **no OI-6b plan is written before gate G1** (Task 8).

## Global Constraints

- Window: `tf = 300 000` ms; at most **10 000 slots**; `start`, `end` aligned `time_ms` (period ends); `end > start`; `end` may be one period past the maximum valid time.
- Request: `venue`, `symbol`, `period`, `start`, `end`, **all required**; any other parameter (`limit`, `as_of`, …) is `400 invalid_parameter`; `venue` is `binance-usdm`, `period` is `5m`.
- Order of checks: parameters (`400`) → open interest enabled (`404 open_interest_disabled`, no database opened) → host clock (`500`) → database (`503`) → series (`404 unknown_series`, message and `details` of OA11).
- Response key order exactly as in the spec 6.3 example; `coverage` has eight integers and `gap_free`; a run is `{state, start, end, slots}`, `start` the `time_ms` of its first slot, `end` the last slot's `time_ms` plus `tf` (exclusive); `present` is never a run; compact JSON, `Cache-Control: no-store`.
- Read only `time_ms` (never value columns) of rows and conflict records; one read transaction; SQLite off the event loop; read-only connection (INV-092 pattern). The new `api` module must avoid the names `find_violations` in `tests/api/test_read_only.py` forbids (INV-014, INV-044).
- A conflict without a stored row is `conflicted` and is counted; `series.oldest_time_ms`/`newest_time_ms` are `MIN`/`MAX` over rows of `open_interest` only. An unaligned stored `time_ms` in the window is `500 internal_error`, never a count.
- No database migration, no configuration key, no change of any existing response; **no existing test is edited** (`tests/api/test_read_only.py` included) and `tests/api/golden/health_ingest_s17.json` is unchanged.
- The domain package stays pure and standard-library only (`tests/test_domain_purity.py`); `api` never imports `collector`. `mypy` is strict over `src`, `tests` and `tools`: the harness is fully typed.
- Register rows (`docs/invariants.md`): an `ENFORCED` row's evidence cell is a comma-separated list of `tests/<file>.py::test_<name>` references that exist, no other text (`tests/test_invariant_register.py`).
- Benchmark: a generated database in a fresh temp dir, never production data, not part of `make check`; no command is invented beyond the new `make bench-overview`. Acceptance criteria AC1 to AC8 and their thresholds are spec 7.2 (AC1 ≤ 45 s, AC4 p99 ≤ 1 s and 0 `503`, AC5 ≤ 432 MiB, AC6 ≤ 1 MB; AC8 belongs to OI-6b).
- Workflow (user's standing rule): failing tests first; this plan and the implementation each get an independent read-only review and all findings are applied; PR squash-merged with the PR title and body written as the squash commit message; **no release tag**. Work on a branch, never on `main`; stage files by name (an untracked `.DS_Store` exists; no `git add -A`). At the end of **every** code task run `make lint typecheck imports` and the task's tests. ## Review Focus

Inputs the spec implies but a straightforward test list would miss; each has its test in the named task.

1. A conflict record at a slot with no row, before `O`, between `O` and `N`, and after `N`: it must be `conflicted` and counted, and must not move `O` or `N` (Task 4, Task 5).
2. A series that stopped long ago (window entirely after `N`, `N` older than the 29-day horizon) and a series whose only data is conflict records (no row: `404 unknown_series`) (Task 5).
3. A hand-edited unaligned stored `time_ms` and a host clock outside the valid range: `500`, and the clock check comes before the database is opened (Task 5).
4. The largest feasible body (10 000 runs): size under 1 MB, and the database read happens off the event loop (body building and `json.dumps` stay on the loop, as for `/v1/coverage`) (Task 5).
5. The harness with a failing call, a deadline reached between phases, and zero calls of one kind: counts are reported, nothing divides by zero, a failed call is never averaged in as a success (Task 1).

A `TransportError` from `fetch` is caught and recorded as a call with `status == 0`. Then one `ThreadPoolExecutor(workers)` serves both phases, `pool.map` per phase: the **candle phase** (one `/v1/coverage` call per instrument with a stored candle) and then the **open interest phase** (one call per instrument); the deadline test `monotonic() - started > deadline_s` precedes **every** call, and a call not made adds to `candle_not_asked` or `oi_not_asked`. `real` requests `/v1/open-interest/coverage?venue=…&symbol=…&period=5m&start=<S+tf>&end=<E+tf>`; `proxy` requests `/v1/coverage` with the candle window (the G0 stand-in); the window is `tools.symbol_overview.window.window_for(as_of_ms)`. `decode_s` is the time of `json.loads` of the body.
  - `make_fetch(base_url: str) -> Fetch`: a new connection per call, GET only, body capped at `tools.symbol_overview.model.MAX_BODY_BYTES`; it reuses `tools.symbol_overview.fetch.http_fetch` for the three paths the tool allows and a same-shaped `http.client` call for the new path (`ALLOWED_PATHS` is not changed here).
  - `summarize(calls: Sequence[CallRecord]) -> dict[str, dict[str, float]]`: over **successful calls only**, per `kind` with at least one: `n`, `p50`, `p95`, `p99`, `max`, `mean`, in ms. Durations are converted to **integer microseconds** before `tools.bench_open_interest_write.nearest_rank` (it takes `Sequence[int]`), and back; a kind with no successful call is absent. `L_mean` is the mean over the successful `candle` and `oi` calls together.
  - `evaluate(results: Sequence[RefreshResult], *, series: int, l_tunnel_ms: float | None) -> dict[str, Any]`: each AC as `{"value": …, "pass": bool | None}`: AC1 (`max duration ≤ 45.0 s`), AC2 (`failed == 0` and both not-asked counts `== 0` in every result), AC3 (`summarize` of all calls), AC6 (largest `body_bytes ≤ 1_000_000`; the maximum `decode_s` reported), AC7 (`D_pred = (2 + ceil(series/4)·2)·(L_mean_ms + l_tunnel_ms)/1000 ≤ 45.0`; `None` when `l_tunnel_ms` is `None`).
  - `evaluate_sustained(probe_ms: Sequence[float], http_503: int, server_peak_rss_bytes: int) -> dict[str, Any]`: AC4 (`p99 ≤ 1000 ms` and `http_503 == 0`) and AC5 (`peak ≤ 432 MiB`).
  - `build_database(path: Path, *, series: int, candle_rows: int, oi_rows: int = 8_640, stress: bool = False, now_ms: int) -> list[str]` returns the symbols; plain SQL through `open_writer` + `migrate`, canonical decimal text values; every series gets candles and open interest ending at the last closed period before `now_ms` (real clock), a few holes and conflict records on every 7th series, one series whose open interest starts 3 days ago; `stress` gives every even open interest slot a row **and** a conflict record and every odd slot no row (alternating `conflicted`/`missing`, the maximum number of runs).
