# FR-6: funding rate on the symbol overview — implementation plan

Design: `docs/superpowers/specs/2026-11-04-fr-6-funding-overview-design.md` (sections cited as "D§x"). Pattern: OI-6b (`2026-11-03-oi-6b-overview-open-interest-page.md`), whose code this plan extends. Issue #28, tracking #15. One branch (`fr-6-funding-overview`), one pull request, squash-merged later by the user; no tag, no version bump.

**Rules for every task:** tests first (failing for the right reason), then the code; no change to the API, the contract, the schema, the Collector or a configuration key; the existing tests of the tool pass **without edits, except the one assertion of `test_oi_window.py` that pins `ALLOWED_PATHS` (Task 2; disclosed in the PR)**; the tool stays standard-library only (`test_boundary.py`); no new member of `INVALID_CODES`; every funding failure is `unknown`/`no_data`, never `ok`. Run `uv run pytest tests/tools -q`, `uv run ruff check`, `uv run ruff format --check`, `uv run mypy` per task and `make check` at the end (commands as in the Makefile; nothing invented).

## Task 1 — model and constants (`model.py`)

- `FUNDING_PATH = "/v1/funding-rates"`, `FUNDING_LIMIT = 2`, `FUNDING_WINDOW_STATES = ("verified", "partly_verified", "unverified")`, `FUNDING_STATUSES = ("no_series", "degraded", "behind", "catching_up", "current")`.
- Frozen dataclasses: `FundingRule(publication_delay_ms, behind_after_ms, quiet_after_ms, backfill_days)` (all four, validated), `FundingWindow(start, end)` (a **separate type**: `end` is inclusive and unaligned, unlike `Window`), `FundingHealth(rule, status, series_count, current, behind, catching_up, conflicted_series, quiet_series)`, `FundingCoverage` (`as_of_ms`, `oldest/newest_funding_time_ms: int | None`, `verified_from/through/at_ms: int | None`, `window_state`, `events_in_window`, `conflicted_events`, `complete`), `FundingReport` (`state`, `reasons`, the same display fields, no rows).
- `Reason` is reused: `slots` carries the count of events (`conflict`) or `0`, `runs` is `0` (design 6).
- Tests: none of their own (data only), covered by the tasks below.

## Task 2 — path and allowed set (`fetch.py`)

- `funding_path(instrument, window)` builds exactly `venue, symbol, start, end, limit=2` with the same encoding as `coverage_path`; `ALLOWED_PATHS` gains `FUNDING_PATH`; the assertion in `test_oi_window.py` (lines ~104-107) is updated to five paths; grep the tests for any other pinned path set.
- Tests in `test_fetch.py`-style new file `test_funding_fetch.py`: exact parameter set and order; special characters encoded; the path is allowed; a not-listed path still raises.

## Task 3 — the funding window (`window.py`)

- `funding_window(window, rule, as_of_ms) -> FundingWindow`: `start = max(window.start, as_of_ms - rule.backfill_days·86_400_000)`, `end = as_of_ms - rule.behind_after_ms + 1` (inclusive); raises `ValueError` when `behind_after_ms` is negative, `backfill_days < 1`, `end < start`, or either value leaves the valid range, or `end - start` exceeds 365 days.
- Tests (`test_funding_window.py`): the formula at `behind_after_ms = 7_230_000`; `end == start` accepted, `end == start - 1` rejected; `backfill_days` 365 (start is `S`), 30 and 1 (start is clamped; the boundary where `T0 - backfill_days·day == S`); range and 365-day limit; negative `behind_after_ms`.

## Task 4 — validation (`validate.py`)

- `funding_health(status, content_type, body, *, health) -> FundingHealth | None | Invalid` as `open_interest_health` (D§4.2): absent key and malformed object → `Invalid("schema", "funding_rate")`, `null` → `None`.
- `funding_result(status, content_type, body, *, instrument, funding_window, health) -> FundingCoverage | Invalid` with the checks of D§4.2 in this order: decode, types, echo, consistency, clock. A `404 unknown_series` stays `Invalid("api_error", "unknown_series")` as for open interest.
- Tests (`test_funding_validate.py`, builders in `funding_helpers.py`): every check of D§4.2 has a test that changes one thing in an otherwise valid body and asserts the code; the derived `window_state` is checked for the three states and for `verified` with `from > start`; `complete` contradictions; `events_in_window > 0` with `series` null; `as_of` at `T0`, `T0 + 70 s`, `+1 ms`, `T0 - 1`; the API's own error codes pass through; a valid body from the three states is accepted; `verified_through_ms` or `newest_funding_time_ms` greater than `coverage.as_of_ms` is `clock_inconsistent`; the health `rule` keeps all four fields.

## Task 5 — judging and the overview object (`judge.py`)

- `judge_funding(outcome, funding_window, as_of_ms, quiet_after_ms) -> FundingReport` as D§4.3: reasons `conflict`, `quiet`, `behind`, `unverified`, `partly_verified` in that order (`partly_verified` only when `verified_from_ms > start`; a span with `from > start` and `through < end` gives both `partly_verified` and `behind`); headline order `FUNDING_STATE_ORDER = (no_data, unknown, conflict, quiet, behind, unverified, partly_verified, ok)`; `ok` iff `complete` and not quiet.
- `FundingPart(status, detail, reports, deadline_hit, funding_not_asked, window, health)`, `funding_summary(reports)`, `_funding_body(report)`; `build_overview(..., *, funding=None)` (keyword-only; refresh keeps passing `open_interest=` by keyword) adds the `funding_rate` blocks of D§6 and the two `refresh` keys **only when `funding` is given**; `candle_not_asked` / `oi_*` untouched. With `funding=None` the object is byte-identical to today's; the refresher always passes a part (`unknown` when health has no `funding_rate` key), so refresh-level tests see **added keys only**.
- Tests (`test_funding_judge.py`): every state and reason alone and together; the headline order; each symbol counted once; the boundaries of D§9 (quiet `==`/`+1`, behind `end`/`end - 1`, partly `start`/`start + 1`); `series` null with a span; a span ending before the window gives `unverified` and `behind`, a span starting after the window end gives `unverified` and not `behind`; text cases for `quiet` with and without a settlement; the clamped-window note; `ok` needs `complete`; `build_overview` with and without funding (existing keys unchanged, a disabled part has no reports, a length mismatch raises).

## Task 6 — the funding phase (`refresh.py`)

- After `_open_interest_phase` and before `build_overview`, `_funding_phase(...)`: `None` → `disabled` with no call; `Invalid` or a window that cannot be built → `unknown` for every symbol with no call; otherwise a new `ThreadPoolExecutor` (4 workers) over **every** instrument with the deadline check before every call (as the open interest phase), `not_asked` counting; the worker judges and drops the answer. `unsupported_series` handled as in the open interest phase.
- Tests (`test_funding_refresh.py`, using the stub fetch and clock of `oi_helpers.py`, extended in `funding_helpers.py`): the request of D§9; call order candle < open interest < funding; **a slow funding fake leaves the candle part and the open interest part identical to a run without funding**; the deadline in the funding phase (`unknown (deadline)` for funding only, `funding_deadline_hit`, `funding_not_asked`, no call after the deadline); candle phase using the whole deadline → no open interest and no funding call; disabled → zero funding calls and the overview equals the baseline; absent/malformed health → no call and `unknown`; `404 funding_rate_disabled` with an enabled health is `unknown`; transport failure, non-200, oversize, bad JSON, echo of another symbol; at most 4 in flight (the real `FakeApi`); only allowed paths (the real `http_fetch`); the snapshot with a partial funding part is 200 and is cached.
- Existing refresh tests pass unedited: health without a `funding_rate` key is the "absent" path, both sides of their candle-only comparison carry the same added `unknown` funding block. The new tests build their own health body (`funding_helpers.py`, from `health_doc`) and their own stripping helper (removes the `funding_rate` blocks and the three `refresh` keys); `stub_routes` of `oi_helpers.py` is not changed.

## Task 7 — the page (`page.html`)

- **Compatibility rule:** the funding status is an **optional last parameter** (default `"absent"`) of `problemSymbols`, `okEntries`, `reasonLines`, `okGroupLabel`, `refreshNotices` and friends; with `"absent"` every output equals today's (the existing `test_oi_page.py` passes unedited); `tiles()` keeps iterating the candle/OI key list, never the combined rank.
- `TEXT` gains the funding strings (states, reasons, notices, columns, labels, the API-figures line); a combined `ORDER` of ten states used for ranking; tiles take the key list of their part so candle and open interest tiles are unchanged; `fundingStatus(data)`, `fundingStateOf(s, status)`, `isProblem`/`worstRank`/`problemSymbols`/`reasonLines`/`okEntries`/`okGroupLabel` extended to three parts; funding notice and deadline line; a Funding column in both tables; the heatmap text line of D§8 (no canvas); `clearStates` clears the new elements (`funding-summary`, `funding-notice`).
- Tests (`test_funding_page.py`, Node as `test_oi_page.py`): element ids kept and new ones present; `clearStates` clears the new elements; every funding reason and state has text; no Czech characters; combined rank; `isProblem` with every combination of the three parts; ok group and its label for each combination of disabled/absent/unknown/enabled; prefixes; notices; deadline line; the page still calls only `/overview.json`.
- Layout, colors and tooltips are checked by hand (Task 10), as before.

## Task 8 — against the real API (`tests/tools/symbol_overview/test_funding_against_real_api.py`)

- As `test_oi_against_real_api.py`: seed a temp database by SQL (schema from the migrations), start the real API with `[funding_rate]` enabled, run the real `Overviewer` with `http_fetch`. Cases: complete series; conflicted; quiet (no row; newest row older than `quiet_after_ms` by `==` and `+1`); behind (`verified_through_ms` exactly `end` and `end - 1`); shallow (`from > start`); unverified (no span, and a span before the window); unknown symbol; funding disabled (no call, overview equals today's). Expected states are written out in the test, not computed by the page's functions.
- This is the test that ties the page's three comparisons to the API's `is_behind` and quiet rule.

## Task 9 — benchmark (`tests/api/bench_overview_refresh.py`, `Makefile`)

- `RefreshResult` new fields (phase times, `funding_not_asked`) have **defaults** (`tests/api/test_overview_bench_model.py` builds it positionally); with funding off the key set `{AC1, AC2, AC3, AC6, AC7}` and every value are unchanged; with funding on `evaluate()` uses the factor 3 in AC7 and includes the `funding` kind in the averaged latency; `bench_server.start_api` gains a `[funding_rate]` table and a request budget that passes `assess_capacity` for 300 and 600 symbols; the sustained run keeps funding off (stated in its output); the bench's `FakeApi` tests keep the funding path off in mode `off`.
- `--funding-mode {off,real}` (default `off`); with `real` the generated database holds funding series (span, a few rows, a few conflicts, one behind, one quiet, one shallow), the API starts with `[funding_rate]` enabled, and `run_refresh` adds a funding phase after the open interest phase with the same deadline and 4 workers; `CallRecord.kind` gains `funding`; the output gains the funding latency summary, `funding_not_asked` and the AC evaluation unchanged. `make bench-overview` passes `FUNDING_MODE` (`--funding-mode $(FUNDING_MODE)`, default `off`).
- **The user wants the measurement thorough, with the total time and what each part of it took** (message of 2026-11-04). So `RefreshResult` also records the **wall time of each phase** (the two head calls, candle phase, open interest phase, funding phase) and the share of each in the total; the output prints, per profile and `N`: total `D` (min, p50, p95, max over the refreshes), per-phase time (same statistics) and its share, per-endpoint call latency (p50, p95, p99, max, mean, count), calls per phase, symbols not asked per phase, and the same figures **with funding off** in the same run (a funding-off refresh is run alongside, so the cost of funding is a measured difference, not a comparison across runs). A human-readable table is printed to stderr next to the one JSON line on stdout.
- Pure parts tested like the existing ones (`tests/api/test_bench_overview_refresh.py` if it exists, else next to it): call order with funding, the deadline in the funding phase, kind counts.
- Run once on the branch at `N = 300` and `N = 600` (`OVERVIEW_PROFILE=smoke` at least if `target` needs hours; say which) and record the numbers in design section 11 and the PR.
