# S16 Gap Detection and Backfill Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** While `quasar-collector run` is up, it finds holes in the stored history of every configured symbol and fills the ones the exchange can still serve, with paged klines, in the idle time between collection rounds. Candles come only through `fetch_once` and the closed-candle gate. **v1 never writes `unavailable_candles`:** a slot the exchange does not serve stays `missing` (D3).

**Architecture:** Pure domain code plans bounded targets and pages, judges each page, and counts skipped cycles. A read-only hole reader lists holes newest-first. A backfill worker runs in an idle window the loop hands it with a deadline; every network call it makes is wrapped so that it is cancelled at a timeout or at stop, while a database write that has started is never cancelled. Pages go through `fetch_once`, which **judges the page against its request before it selects or writes anything** (D4). No schema, contract or ADR change; no new writer method.

**Tech Stack:** Python 3.12 stdlib (`sqlite3`, `asyncio`), existing `fetch_once`, `run_collection_loop`, `AsyncCandleWriter`, `RateLimitedSource`, `reconcile_reader`; pytest, mypy strict, ruff, import-linter. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-20-market-data-v1-design.md` (§8 S16, D5, §11 item 11), `docs/architecture.md` (§4.1, §5.3, §6 items 2, 3, 4, 7), `docs/adr/0002-sqlite-schema-v1.md` (P-6, P-7, P-9), `docs/adr/0001-binance-ingestion-fidelity-and-closed-candles.md` (D-E, D-F, P-3, P-4, P-6). Earlier plans: `2026-10-27-s15-checkpoints-and-restart-reconcile.md` (D1, D5, D7, "Residual risks"), `2026-10-26-s14-collection-loop.md`. Follow-ups F-8, F-10, F-13.

## Facts checked (2026-10-27, revised twice)

Read in the code unless a line says it was run:

- **Adapter.** `BinanceUsdmSource.fetch_klines` calls `fapiPublicGetKlines({"symbol","interval","limit"})`; no range, no timeout of its own. CCXT's `timeout` is 10 000 ms and `enableRateLimit` is on (S14 plan, checked by running the client); the adapter sets neither.
- **CCXT cancellation (RUN, 2026-10-27, scratch scripts outside the repository; CCXT 4.5.89, aiohttp 3.14.5, Python 3.12.5; a local plain-HTTP server, not Binance, no TLS).** (1) Cancelling an awaiting `fapiPublicGetKlines` whose response never comes returned in about 1 ms; no client task stayed alive; the next request on the same client succeeded (52 ms). (2) With CCXT's throttle slowed to one request per 2 s and four requests queued, cancelling the second queued one: the other three still completed, but the **total time was unchanged (6.0 s, the same as without the cancel): a cancelled request keeps its turn in CCXT's throttle**, so a cancelled backfill request can still delay a later request by one throttle interval. After `close()` no client task was left. **Not verified:** TLS to the real host, many cancels in a row, connection reuse after a cancel against Binance, 418/429 behaviour. Task 2 turns (1) and (2) into default-suite tests on a local socket.
- **Limiter.** `RateLimiter.acquire` is one FIFO `asyncio.Lock`; a cancelled waiter, queued or sleeping, consumes nothing (module docstring). A backfill request waiting there delays every request queued behind it.
- **Writer.** `AsyncCandleWriter.write` runs on one FIFO worker thread. Cancelling the awaiting task does not stop a running job; the caller cannot learn the result, and `_WriteWatch` marks the symbol uncertain (exit 4 for the process). A write queued by backfill ahead of a round's write delays that write by the queued job's duration. SQLite waits are bounded per lock wait by `busy_timeout` (5 000 ms), **not in total**.
- **Time.** `fetch_once` takes one server-time observation per call and evaluates `server_lower_bound(observation, request_ns, request_wall_ms, None, DEFAULT_TIME_TRUST)` at the klines send time: `max_rtt_ms=2000`, `max_uncertainty_ms=2000`, `max_age_ms=60000`, `max_drift_ppm=500`, `precision_margin_ms=50`, `max_clock_divergence_ms=100`. Rejections: `NO_OBSERVATION`, `MONOTONIC_REGRESSION`, `RTT_TOO_LARGE`, `AGE_TOO_LARGE`, `UNCERTAINTY_TOO_LARGE`, `SERVER_TIME_REGRESSED` (cannot fire today, the previous observation is `None`, F-8), `CLOCK_DIVERGENCE`. With untrusted time every candle stays pending and nothing is written.
- **Order of operations in `fetch_once` today:** server time, `fetch_klines`, `parse_klines` (all-or-nothing on shape, types, `closeTime`, strictly increasing `openTime`), `select_closed_candles`, **`writer.write(selection.eligible)`**. Anything that must prevent a write has to run between `parse_klines` and `select_closed_candles`.
- **Loop.** After a round, `run_collection_loop` computes `next_wake_ms(clock.wall_ms())` and sleeps. **If the work between rounds ends after the boundary, today's loop does not start that round late: `next_wake_ms` returns the following boundary and a whole cycle (5 m) is skipped, and `RoundReport` shows nothing about it** (S14 Decision 4 chose skipping over queueing for slow rounds). A "lateness" measured from the planned boundary would read 0 in that case; the skipped cycle must therefore be counted from the actual round starts (D5).
- **Schema.** `unavailable_candles` exists (migration 001, P-6), immutable, `reason IN ('EXCHANGE_NO_DATA')`. P-7 reports a slot stored and unavailable as `conflicted`. No code writes it; `GET /v1/coverage` renders it as `U`.
- **Binance semantics, from memory and NOT verified.** `/fapi/v1/klines`: `startTime`/`endTime` filter on the candle open time, both inclusive; without them the newest rows; ascending; maximum `limit` 1500; request weight grows with `limit` (1 below 100, 2 below 500, 5 up to 1000, 10 above). ADR-0001 could not read the endpoint page. **Every rule below is designed so that correctness does not depend on these statements:** the page is judged on the client before anything is written (D4), and a violation fails the page closed. Task 0 step 3 turns them into captured evidence.

## Global Constraints

- Collector and API stay independent; `domain` imports nothing from `collector`, `api`, `storage`, ccxt, fastapi, talib or `sqlite3`.
- `fetch_once` is the only path that stores candles; the closed-candle gate (`select_closed_candles`) has one implementation. Backfill adds no second gate, no new `CandleWriter` method, and calls no writer directly.
- Never fabricate. Backfill writes **no** `unavailable_candles` row. Exchange silence (empty page, skipped slot, short page) is never presented as unavailability; the slot stays `missing`.
- A local clock decides only *what to ask for* and *when*. It never marks a slot and never confirms a candle: confirmation is `fetch_once`'s server-time gate.
- Idempotent and restart-safe: holes are re-derived from stored facts each cycle (S15 D1). In-process memory (back-off, exhaustion, suspension) is a cache that may be lost; losing it costs requests, never data.
- Current collection has priority within the bounds of D5. Nothing here claims an exact round start; every delay and every skipped cycle is reported.
- No schema change (P-9), no public contract change; `api-v1.md` gets wording changes only (lines 9 and 84).
- Tests use fakes, fixtures and a local socket; no live exchange in the default suite. Commands: `make test`, `make check`, `make bench`.

## Review Focus

Inputs the spec implies and the main tests do not exercise; each has a named test.

1. A page cut by `limit` proves nothing about slots after its last row (Task 1 `test_a_full_page_continues_after_its_last_row_and_a_short_page_ends_the_target`).
2. A page with rows before `startTime`, after `endTime`, repeated, out of order, misaligned or too many, or a page with one bad row among good ones: **zero writes** (Task 2 `test_an_invalid_page_writes_nothing`, Task 5 `test_an_invalid_page_changes_no_database_row`).
3. A stalled klines request, a stuck limiter, a slow server, a write that overruns: backfill gives up at its timeout, the overrun is reported, and a skipped cycle is counted, never silent (Tasks 3, 6, 7).
4. A new, halted or delisted symbol returns nothing or only newer rows: no request storm, no `unavailable` (Task 5 `test_a_symbol_with_no_older_data_is_asked_once_per_ttl`, `test_nothing_is_written_to_unavailable_candles`).
5. Untrusted server time, stale observation, wall-clock step during backfill: nothing stored, no progress claimed (Task 5, three tests).

## Decisions (proposed; HARD STOPs are in Task 0)

1. **Backfill is derived, not remembered.** Each cycle reads holes from the database (S15 D1); a restart repeats the read and already stored pages are duplicates.
2. **Targets and horizon.** Holes are filled newest first, only inside the horizon `[floor(now_local) - backfill_days·day, forming_open)` (default 30 days, spec D5). Targets per symbol: (a) at most `K = 20` newest interior hole runs (read-only query), (b) the *head* `[horizon_start, oldest_stored)`, or `[horizon_start, forming_open)` for a symbol with no candles. Older than the horizon is never requested.
3. **v1 does not write `unavailable_candles`.** An immutable row from a response is not safe evidence: Binance revised a closed candle up to ~8 s after close (ADR-0001 E-5), the recheck sampled one instrument for 67 min (E-7), a bracketed gap can be a transient outage that the exchange later fills, and a later real candle would turn the slot into a permanent `conflicted` (P-7, Q3 has no resolution path). Consequence: holes the exchange does not serve stay `missing`, `unavailable_slots` stays 0, and S15's `needs_s16` keeps counting them. **What would be strong enough evidence** (recorded, not built): a first observation persisted with its time (a table: new migration, P-9 approval), a second independent observation at least 24 h later, both with trusted time and both bracketing the slot with eligible rows, and an operator-visible report before the first write. That is a schema change and the user's decision (HARD STOP 1).
4. **Paging, and the page is judged before anything is written.**
   - A target is walked by pages. Page `i` is a `PagePlan(start_ms=s, end_ms=target_last_open_ms (inclusive), limit=min(MAX_LIMIT, slots in [s, target_last]))`.
   - **Minimal interface change:** `FetchOnceConfig` gets one optional field `page: PagePlan | None = None` (when set, `limit` must equal `page.limit`; the request carries `startTime = page.start_ms` and `endTime = page.end_ms`). `fetch_once` runs, **between `parse_klines` and `select_closed_candles`**, `outcome = judge_page(config.page, open_times, timeframe_ms)` (pure, domain). A `PageViolation` propagates before the selection and before `writer.write`, so an invalid page stores nothing by construction of the order of operations. `FetchOnceReport` gets `page: PageOutcome | None`. The backfill never judges again and never writes.
   - `judge_page` rejects the page whole when: a row is before `start_ms` or after `end_ms`; a row is not aligned to the timeframe; rows are not strictly increasing (duplicate or descending); `len(rows) > limit`. (Shape, types and `closeTime` consistency are already `parse_klines`' all-or-nothing job and also happen before any write.)
   - Outcomes of a valid page: **EMPTY** (0 rows) → the target is exhausted, no progress; **FULL** (`len == limit`) → `next_start = last_open + tf`, strictly `> start_ms`, the target ends when `next_start > end_ms`; **SHORT** (`0 < len < limit`) → the exchange returned all it has up to `end_ms`; the target ends. Page cap per target: `ceil(slots / MAX_LIMIT) + 1`; exceeding it is a bug and fails the slice.
   - **Candle-level invalidity is not page-level.** A well-formed row that fails `validate_candle` (e.g. OHLC) or is still pending is handled exactly as in a round (`selection.invalid` / `selection.pending`); the rest of the page is stored. It is counted in the slice report (`invalid`, `pending`) and its slot stays a hole.
   - **Three different statements, never merged (pure `judge_target` covers only the first).**
     1. *What the exchange served* (`TargetResult`): `SERVED_ALL` when the rows returned over the walk equal the slots of the target, `SERVED_NONE` when no row was returned, otherwise `SERVED_SOME`. It is about the HTTP answer and says nothing about storage.
     2. *What the writer reported* (`stored`, `duplicates`, `conflicts`, `invalid`, `pending`): counters of one `fetch_once` result; a write report is not evidence that a slot is now present (S15 `test_a_write_report_is_not_evidence`).
     3. *What was recovered*: **only a database read-back counts, and only when the change can be attributed to this slice.** Before the first page and after the last page of a slice the worker reads, with `read_present` (Task 4), the **set of open times present in `candles`** for **the same fixed tuple of planned targets** (`[first_ms, end_ms)` ranges captured once, passed unchanged to both reads; rows outside those ranges, of other symbols or timeframes, are not read). From the two sets `B` (before) and `A` (after) and from `S` = the open times of `selection.eligible` the closed-candle gate handed to the writer in this slice, the pure `attribute_recovery` (Task 1) derives: `new_in_targets = |A \ B|` (a database fact, unattributed), `missing_in_targets = target slots - |A|` (a database fact), and `recovered = |(A \ B) ∩ S|` **only when attribution is `OK`**. Attribution is `OK` only if all hold: (a) both reads succeeded; (b) `B ⊆ A` (candles are immutable; otherwise `ANOMALY`, e.g. rows removed by someone with file access); (c) `(A \ B) ⊆ S`, i.e. every newly present slot is one this slice sent (otherwise `FOREIGN_WRITES`: another writer was active in the targets during the slice: a second collector process, `fetch-once`, or a late write of a cancelled round still draining on the writer thread); (d) every write outcome of the slice was known (otherwise `WRITE_UNKNOWN`); (e) the writer's `Σ inserted` equals `|(A \ B) ∩ S|` (otherwise `REPORT_MISMATCH`, e.g. another writer inserted a slot this slice only saw as a duplicate, or the report lies). **The write report can only downgrade a recovery to unverified; it never contributes a number.** Any attribution other than `OK` prints `recovered=unverified`; the database facts `new_in_targets` and `missing_in_targets` are still printed when the reads succeeded. If a read fails: `READBACK_FAILED`, everything `unverified` (as S15 INV-051). A failing *before* read means the slice starts no page. Within this process no write runs concurrently with the hook (D5), except the drain of a cancelled or uncertain write from the previous round, which is why (c) exists. Conservative by design: a legitimate recovery is reported `unverified` whenever a foreign write touches the targets in the same slice.
     4. *Page atomicity, not target atomicity.* An invalid page stores nothing; pages of the same target written before it stay stored (each page is a separate `fetch_once`). This is why recovery is measured per slice from the database and never assumed per target.

5. **Deadline-aware idle window; guarantees stated as they follow from the order of operations.**
   - **The window.** After `on_round` and the S15 hook the loop plans once: `planned_ms = next_wake_ms(wall_ms())`, `remaining_ms = planned_ms - wall_ms()`, `due_mono_ns = monotonic_ns() + remaining_ms·1e6`. It builds `IdleWindow(due_mono_ns, deadline_mono_ns = due_mono_ns - IDLE_RESERVE_MS·1e6, source, sink_for, stop)` and awaits `idle_work(window)` if `deadline_mono_ns > monotonic_ns()`. **Everything inside the window is measured on the monotonic clock** (page-start test, `DeadlineSource` timeouts, overrun), so a wall-clock step cannot extend the window, shorten it, or be mistaken for an overrun. After the hook the loop sleeps the monotonic remainder `max(0, due_mono_ns - monotonic_ns())`. **There is no jump to the following boundary after idle work:** a round delayed by idle work starts at once (the only change to the S14 sleep, and only when a hook is installed). A round that overran its own successor boundary keeps the S14 skip.
   - **Constants.** `REQUEST_TIMEOUT_MS = 5_000` (below CCXT's 10 s; covers the limiter wait **and** the request), `WRITE_RESERVE_MS = 5_000` (one SQLite lock wait, an assumption not a bound), `PAGE_BUDGET_MS = 2·REQUEST_TIMEOUT_MS + WRITE_RESERVE_MS = 15_000`, `IDLE_RESERVE_MS = 15_000`. A page starts only if `monotonic_ns() + PAGE_BUDGET_MS·1e6 <= window.deadline_mono_ns`.
   - **Network phase.** Every source call goes through `DeadlineSource` (outside `RateLimitedSource`): raced against `min(REQUEST_TIMEOUT_MS, time left)` and against `stop`, then cancelled and raised as `SourceError`. Cancelling a read and a limiter waiter is safe (Facts). A cancelled request keeps its CCXT throttle turn (Facts): at most one backfill request is in flight, so the delay it can add to a later round request is bounded by one throttle interval.
   - **Write phase.** The backfill never cancels `fetch_once` and never a started write. A stop waits for the write. If the write exceeds `WRITE_RESERVE_MS`: nothing can interrupt it; the hook does not return; the round waits (no overlap); on return the round starts at once and reports `idle_overrun_ms = mono_hook_end - due_mono_ns` (>0). **Operational boundary:** the delay of the next round equals the duration of that write beyond the reserve. It is not bounded by this plan (SQLite waits are bounded per lock wait only); it is bounded in practice by the single in-process writer. **Testable failure mode:** a sink that blocks the hook until `T` ms (monotonic) after `due_mono_ns` yields `idle_overrun_ms == T`; when `T` crosses a cycle boundary, `skipped_rounds >= 1`; both are printed, plus a stderr warning. An *overrun* is a window whose hook ended after `due_mono_ns` (`idle_overrun_ms > 0`, monotonic). The `Backfiller` measures it itself at its return for the suspension rule; the loop measures the same quantity when the await returns and prints it; with a fake clock they are equal, on a real clock they may differ by the scheduling latency of the return. After `OVERRUN_LIMIT = 2` consecutive overruns (a window without overrun resets the count) the `Backfiller` suspends itself for the rest of the process. **Suspension output and effect:** once, on stdout `backfill suspended reason=idle_overrun consecutive=2 until=restart` and on stderr `warning: backfill suspended after 2 consecutive idle overruns (last idle_overrun_ms=…); restart to resume`. After that `run_idle` returns at once: **no hole read, no source call, no write**, in every later window; there is no API to resume. A wall-clock step is not an overrun and never counts (D5, last bullet).
   - **Measuring delay, overrun and skipped rounds (three different clocks of evidence).**
     - `idle_overrun_ms` and `lateness_ms` are **monotonic**: `due_mono = mono_at_planning + remaining_ms`; `idle_overrun_ms = max(0, mono_hook_end - due_mono)`; `lateness_ms = max(0, mono_round_start - due_mono)`. They are immune to wall-clock steps, so a step cannot be blamed on backfill and cannot trigger its suspension. Each iteration computes them from its own planning instant, so repeated overruns do not accumulate.
     - `skipped_rounds` is **schedule-based (wall)** from the actual round starts: `max(0, cycle(started) - cycle(previous_started) - 1)` with `cycle(t) = (t - delay) // tf` (pure, `domain.schedule.cycles_skipped`). A cycle in which no round started is skipped, whatever the cause (slow round, backfill write, clock step); `lateness_ms` alone cannot show it and is not used to claim there was none. A backward step gives 0, never a negative number.
     - `clock_step_ms` reports a step: `(wall_round_start - wall_previous_start) - (mono_round_start - mono_previous_start)` in ms when its absolute value exceeds `max_clock_divergence_ms` (100, the existing gate), else 0. `skipped_rounds > 0` together with `clock_step_ms != 0` is a clock event, not a load problem; the operator sees both. After a step the wall-based schedule re-anchors to the stepped clock, which is the existing S14/S15 behaviour (F-13) and is not changed here.
     - All four fields, and `idle_overrun_ms`/`skipped_rounds` as stderr warnings when non-zero, are printed; the first round reports 0 for all.
   - **What follows from this order and what does not.** Follows: backfill starts no page it cannot finish within its own network timeouts before `due_mono_ns - IDLE_RESERVE_MS`; it never overlaps a round; on stop it returns after at most the current write; it cannot skip a cycle silently. Does not follow: that rounds start at their boundary (a write can overrun; a round can overrun the next boundary by itself); that a skipped cycle loses data (each round fetches the newest `limit` rows, which is incidental, S14 Decision 4, not a guarantee).
6. **Writes use the loop's per-symbol sink (`_WriteWatch`),** so an unknown outcome during backfill marks the symbol uncertain exactly as in a round (exit 4, F-8).
7. **Failures, back-off, restart.**
   - A `SourceError`, `KlineParseError` or `PageViolation` ends that symbol's slice and doubles its back-off: `min(2^n, MAX_BACKOFF_CYCLES = 12)` cycles; a success resets it. A symbol the exchange does not know (delisted) is an ordinary source error and backs off to 12 cycles. A storage error from a backfill write is fatal like a round's.
   - A target whose result is `SERVED_NONE` or `SERVED_SOME` is exhausted for `UNPROVEN_RETRY_CYCLES = 288` cycles (one day). Exhaustion and back-off live in memory.
   - **Restarts.** After a restart the memory is empty: each symbol with holes costs at most `K + 1 = 21` requests once per start (newest first, empty results exhaust at once). **Over repeated restarts the count of such probes is not bounded** (it would need a persisted marker: a schema decision, F-15), **but their rate is**: requests go through the 100 ms limiter, only inside idle windows, one in flight, at most `floor((idle time) / page time)` per cycle. A crash loop therefore costs requests at the normal backfill rate, not a burst. Stated as a residual risk, not as a guarantee.
   - A `Backfiller` suspended by D5 stays suspended until restart.
8. **Output.** One stdout line per symbol slice, with the three statements of D4 in separate field groups: `backfill symbol=… pages=… | served_all=… served_some=… served_none=… | stored=… duplicates=… conflicts=… invalid=… pending=… | new_in_targets=… recovered=… missing_in_targets=… attribution=… | status=…`. `status ∈ {no_targets, progress, backoff, time_untrusted, suspended}`; there is no `done`. `new_in_targets` and `missing_in_targets` are database facts (integers, or `unverified` when a read failed); `recovered` is an integer only when `attribution=ok` and otherwise the word `unverified`; `attribution ∈ {ok, foreign_writes, report_mismatch, write_unknown, anomaly, readback_failed}`. No other field implies recovery. `no_targets` means only that the reader found no hole inside the horizon; it says nothing about history older than the horizon or before the symbol's first row (S15 INV-051). No line says "complete", "filled" or "unavailable". Round lines gain `lateness_ms= idle_overrun_ms= skipped_rounds= clock_step_ms=`.
9. **Hole discovery cost.** The reader runs per symbol at most once per `RESCAN_CYCLES = 12` cycles and after any slice that stored something; round-robin, one slice per symbol per window until the deadline. Its cost is F-10 (HARD STOP 2).
10. **Out of scope, recorded as limits:** writing `unavailable_candles` (D3), health and readiness (S17), live gap counters, resolving `conflicted` slots (Q3), 418/429 cool-off (F-8), per-exchange concurrency for backfill, other timeframes, other datasets, persisting back-off or exhaustion (F-15).

### Task 1: Pure backfill logic

**Files:** Create `src/quasar_market_data/domain/backfill.py`; test `tests/domain/test_backfill.py`.

**Interfaces:**
- Produces:
  - `@dataclass(frozen=True) class BackfillTarget: first_ms: int; end_ms: int` (half-open, aligned, `first_ms < end_ms`); `last_open_ms(target, timeframe_ms) -> int` (= `end_ms - timeframe_ms`); `slot_count(target, timeframe_ms) -> int`.
  - `plan_targets(*, horizon_start_ms: int, forming_open_ms: int, oldest_stored_ms: int | None, interior_runs: Sequence[tuple[int, int]], timeframe_ms: int) -> tuple[BackfillTarget, ...]` (newest first, interior runs clipped to the horizon, head last, empty when the horizon is empty).
  - `@dataclass(frozen=True) class PagePlan: start_ms: int; end_ms: int; limit: int` (`end_ms` is an inclusive open time) and `plan_page(target, start_ms, timeframe_ms, max_limit) -> PagePlan`.
  - `class PageViolation(ValueError)`; `class PageKind(StrEnum): EMPTY, FULL, SHORT`; `@dataclass(frozen=True) class PageOutcome: kind: PageKind; rows: int; next_start_ms: int | None` (`None` when the target ends).

## Residual risks, open HARD STOPs

**HARD STOPs still open:** (1) the data model, v1 without `unavailable_candles` (user); (2) the scan cost F-10, `make bench` not run (user, before real use); (3) Binance range semantics and weights (live probe, before the first real run).

1. **Holes the exchange does not serve stay `missing`** in every coverage answer; indicators keep refusing them (S18). Fail-closed, and noisy for new or halted symbols.
2. **A write blocked on SQLite delays the next round by its duration beyond the reserve, without a bound in this plan.** The effects are reported (`idle_overrun_ms`, `skipped_rounds`), repeated overruns suspend backfill, but a single long block can still cost a cycle. Data is not lost by a skipped cycle only because each round fetches the newest `limit` rows (incidental, S14).
3. **CCXT cancellation is verified only on a local plain-HTTP server,** and a cancelled request keeps its throttle turn (a bounded extra delay of one throttle interval). TLS, many cancels in a row and Binance's behaviour are not verified.
4. **Restarts re-ask:** exhaustion and back-off are in memory; a crash loop repeats up to 21 probes per symbol per start at the normal, rate-limited backfill rate; the count over many restarts is unbounded (F-15).
5. **Binance semantics and request weight unverified** (HARD STOP 3). Client-side judgement makes a wrong assumption fail closed; it cannot make backfill efficient if it is wrong.
6. **Rescan cost** at 600 symbols (F-10) is unmeasured; cadence bounds requests, not the scan.
7. **A cold 30-day backfill of 600 symbols** is about 5 400 requests of 1000 rows; at the 100 ms spacing and 15 s page budgets inside a 5-minute cycle it fills over many cycles by design.
8. **The uncertain-write flag** is process-local (F-8); a restart re-derives the holes, which is recovery, not proof.
9. **`served_all` is not recovery and not completeness:** it says the exchange returned every slot of a target at that time. Recovery is the read-back difference only, and even that is a statement about the instant of the read; a later revision is S8 conflict handling.
10. **The read-back reads two sets of open times per slice** (at most `backfill_days·288 = 8 640` integers per symbol, primary-key range reads, asserted by the query-plan test); it does not share the F-10 scan-cost caveat, which belongs to the hole discovery.
12. **Attribution is conservative:** any foreign write in the targets during a slice makes that slice's `recovered` `unverified`, even if backfill also recovered slots. The database facts (`new_in_targets`, `missing_in_targets`) stay available. A foreign writer that writes exactly the slots this slice sends, with matching counts, cannot be told apart by this method; it requires `inserted` to match, and two writers racing for the same slot produce a duplicate on one side, which is detected (`report_mismatch`). A third-party writer that inserts a slot after the after-read is outside the slice by definition.
11. **A wall-clock step re-anchors the schedule** (F-13/S14); the plan reports it (`clock_step_ms`) and keeps it out of the overrun and suspension logic, but does not correct the schedule.
