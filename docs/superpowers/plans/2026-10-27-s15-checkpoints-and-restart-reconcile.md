# S15 Checkpoints and Restart Reconcile Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `quasar-collector run` starts by reading what the database proves for each configured symbol, in two separate statements that are never merged: whether the recent *window* has confirmed gaps, and whether the *history* between the oldest and the newest stored candle has holes. It fetches in the first round the absent slots that the existing newest-rows request can still reach, and reads the database again afterwards. It never says that history is complete, and it never says that anything was recovered except through a database read.

**Architecture:** A pure domain module classifies one series from stored facts (it reuses `classify_span_at`, so the slot states are the ones `GET /v1/coverage` already uses) and computes request sizes from a `now` it is given. A collector module reads the facts on its own read-only connection in a worker thread: a bounded window read plus a series-wide hole aggregate over the primary key. The loop gains two optional inputs: for the first round, the oldest wanted slot per symbol (the request size is recomputed from the clock on every attempt), and an async hook awaited once after the first round. The CLI wires reconcile before and after. No schema, contract or ADR change.

**Tech Stack:** Python 3.12 stdlib (`sqlite3`, `asyncio.to_thread`), existing `classify_span_at`, `fetch_once`, `run_collection_loop`, `open_reader`; pytest, mypy strict, ruff, import-linter. No new dependency.

**Spec:** `docs/superpowers/specs/2026-10-20-market-data-v1-design.md` (§8 S15, S16, §11.3, §11.4), `docs/architecture.md` (§4.1 Backfill/recovery, §5.3, §6 items 1 to 3 and 6), `docs/adr/0002-sqlite-schema-v1.md` (C-4, P-6, P-7, P-9), `docs/adr/0001-binance-ingestion-fidelity-and-closed-candles.md` (D-E, P-5, P-6). Earlier plans: `2026-10-26-s14-collection-loop.md`, `2026-10-25-s11-coverage-calculation.md`.

## Task 0: Decision gate (hard stop, no code)

This plan does **not** add a checkpoint table. `docs/architecture.md` §6 item 1 says "load persisted collection checkpoints"; ADR-0002 P-9 and line 176 say S15 checkpoints would be a new migration with its own approval. The plan reads "persisted checkpoint" as "progress that survives a restart" and derives it from the immutable `candles`, `candle_conflicts` and `unavailable_candles` tables (D1). That is a reinterpretation of a wording, so it is the one real decision gate of this slice:

- [ ] **Step 1:** Ask the user to accept D1 or to ask for a checkpoint table. If a table is wanted, stop: that needs an ADR-0002 amendment first and Tasks 1 to 4 are re-planned. **Do not decide this on the user's behalf.**
- [ ] **Step 2:** Record the answer at the top of this file. Only then start Task 1.

**HARD STOP 2 (before production use, not before implementation): the start-up cost of the history read (D13).** Tasks 1 to 5 may be implemented without it. But the series-wide hole aggregate reads every stored candle of every configured symbol before the collector starts, and only a measurement can say whether that is acceptable. After Task 2 the benchmark must be run on the `target` profile and its numbers shown to the user; if the acceptance criteria of D13 are not met, the user chooses between the options listed there. **Nothing is decided here, and `quasar-collector run` must not be used against a real database with a long history until the user has accepted the numbers.**

Not gates, but open to review: the pre-start refusal of a `--publication-delay-ms` that no round can ever serve (D9, exit 2); the `history_complete` label is reserved and never emitted (D6; a future ADR, together with S20 listing evidence, may introduce it).

## Global Constraints

- Collector and API stay independent; `domain` imports only the stdlib allowlist and itself (INV-004), reads no clock (every function takes `now_ms`/`as_of_ms`) and no I/O; `storage` is not touched.
- Every candle reaches the writer only through `fetch_once` (INV-007). Reconcile reads and reports; it never writes, never calls the source, and never creates a candle, price, volume or `unavailable_candles` row, and it never marks anything unavailable.
- A slot counts as present or recovered only through a database read. A write report, a successful request or an exit code is never evidence. When the read fails the claim is withheld (`unverified`).
- Fail closed: a failing pre-start read exits `1` before any network call and before the writer opens; no reconcile output uses the word "complete" for a window or for history, and `window_no_gaps` is never presented as full coverage.
- Restart-safe and idempotent: starting twice, or after an interrupted start, leaves the same stored rows.
- A conflicted slot is reported, never retried into a different result (ADR-0001 P-6); conflicts do not enlarge any request.
- No schema, public-contract or ADR change; no new dependency; no live-exchange test in the default suite; tests never touch production storage.
- Priorities when in conflict: correctness, data integrity, reliability, simplicity, performance. Verification: `make check` before **every** commit; during a task `uv run pytest <path>`. No other commands are invented.

## Reach arithmetic (all numbers used by the tests)

Notation: `tf = 300 000`; `L = MAX_LIMIT = 1000`; `K = REACH_MARGIN_SLOTS = 2`; `F(w) = align_down(w)`; slots are written as offsets from `F` at the read, `F0`.

1. **A request returns** the rows `[F_s - (L-1)·tf, F_s]`, `F_s` the server's forming slot (ADR-0001 evidence). The attempt knows only its local clock. **The one time assumption (A1) is an operating assumption, not a property that Binance guarantees or that is checked before the request:** the server's forming slot is at most `K` slots ahead of the local one, `F_s <= F(w) + K·tf`. It is the same class of assumption S14 already makes by deriving the target from `clock.wall_ms()`. It is diagnosed after the fact (item 8, D12); when it fails, the symptom is a slot that is not reached, which the post-check reports from the database. No claim depends on A1.
2. **Request size, computed on every attempt from the clock at that attempt:** `attempt_limit(now, g) = min(L, max(default_limit, (F(now) - g)/tf + 1 + K))` where `g` is the oldest absent slot wanted. It covers `g` iff `F_s - g <= (F(now) - g) + K·tf`, i.e. under A1. Nothing depends on how long the read, the round or the retries took, because the clock is read at the attempt.
3. **Reach at the read:** a slot `g` is reachable by a request made in the same slot iff `(F0 - g)/tf + 1 + K <= L`, i.e. `g >= ws := F0 - (L - 1 - K)·tf = F0 - 997·tf`. The window is the closed slots `[ws, T]` (clamped at the first valid slot); its end is `T + tf <= F0`.
4. **Example, at the read:** `T = F0 - tf` (delay 15 s, as_of 20 s after the boundary). `g = ws = F0 - 997·tf` → `attempt_limit = 997 + 1 + 2 = 1000` (reached, the request's oldest row is `F0 - 999·tf`). `g = F0 - 990·tf` → `993`. `g = T - 59·tf`, i.e. newest stored `T - 60·tf` → `(F0 - g)/tf = 60`, `60 + 1 + 2 = 63`.
5. **Drift (round starts or retries late):** the attempt for `g = ws` made 3 slots later (`F' = F0 + 3·tf`) needs `1003 > L` → capped at `1000`; oldest row `F' - 999·tf = F0 - 996·tf`; the slot `F0 - 997·tf` is **not** reached, exactly one slot. The post-check's window has moved with the clock (`ws' = F' - 997·tf = F0 - 994·tf`), so the lost slot lies older than it: it appears as a one-slot hole in the history (`history_holes=1`, `needs_s16=1`), not as `missing`. For `g = F0 - 990·tf` the same drift needs `996 <= 1000`: reached. A retry that happens after a boundary passes recomputes: `63` becomes `64`.
6. **Unreachable tail:** newest stored `n < ws` → the slots between them cannot be requested: `unreachable_tail = (ws - n)/tf - 1`. For `n = F0 - 2001·tf` (`T - 2000·tf`): `(F0 - 997·tf - F0 + 2001·tf)/tf - 1 = 1004 - 1 = 1003`.
7. **Long publication delay:** `max (F - T)/tf = ceil(delay/tf) + 1 =: m`. For delay 700 000: `m = 4`; at `w = F0 + 10 s`, `T = F0 - 4·tf`, the window ends at `F0 - 3·tf`; the slots `F0 - 3·tf .. F0 - tf` are in the rows but pending, and the window loses none of its reach. A round can reach `T` every time iff `m + 1 + K <= limit`. For delay 30 000 000 (100 slots): `m = 101`, `101 + 1 + 2 = 104 > 100` → every round with the default `--limit 100` fails to reach `T`; the plan refuses to start (D9). With `--limit 104` it starts; delay 30 000 001 needs `105`. A delay so large that `m + 1 + K > L = 1000` leaves an **empty window** (`ws > T`): status `TARGET_OUT_OF_REACH`, and the steady-state check refuses it for every `--limit`.
8. **Observed lead (the A1 diagnostic, D12):** after each successful `fetch_once` of round one, `F_s_observed = max(key.open_time_ms)` over `selection.eligible + selection.pending` (the newest returned row, which ADR-0001 observed to be the forming candle) and `lead = (F_s_observed - align_down(local_wall_after_fetch))/tf`. Examples: server three slots ahead (`F_s = F0 + 3·tf`, local wall `F0 + 40 s`) → `lead = 3 > K` (violated); equal clocks → `0`; server one slot behind → `-1` (not a violation; over-requesting is harmless). A request made with `lead > K` can miss exactly `lead - K` of the oldest wanted slots: for `g = ws` and `lead = 3` the oldest returned row is `F0 + 3·tf - 999·tf = F0 - 996·tf`, so the one slot `F0 - 997·tf` is missed; for `lead = 2` the oldest row is `F0 - 997·tf = ws`, reached. Error of the measure: the wall clock is read after the response, so a boundary that passes during the call can raise `lead` by 1; no rows means no observation and nothing is claimed; the reading "the newest row is the forming candle" is an ADR-0001 observation, not a proof.

## Decisions made in this plan (open to review)

1. **D1 No checkpoint table; the restart state is derived from the stored facts** (gate in Task 0). The three immutable tables are written in the batch transaction (INV-034), so they cannot disagree with a separate row. State that is **not** derivable, and therefore not kept across restarts: "tried and the exchange had nothing" (S16: `unavailable_candles`), the in-process write-uncertainty flag (F-8), and S16's backfill progress. What would change this: S23 shows the start-up read is too slow at 600 symbols, or S16 needs state that is not a fact about a slot. **An old hole is not in this list** (D4): it is a fact (absent rows between present rows) and is read series-wide at every start.
2. **S15 versus S16.** S15 recovers only what the existing newest-rows request reaches. S16 owns everything it cannot: paging with `startTime`/`endTime`, `unavailable_candles` writes, detection while running, the non-starvation policy, and any proof that history exists at all. S16 reuses `first_round_wanted_from` (D7) instead of adding a parallel mechanism. S15's output states the exact number of slots that need S16 (`needs_s16`).
3. **Window and states.** Window `[ws, T]` as in the arithmetic section; classified by `classify_span_at` from `max(ws, oldest stored)` (slots before the oldest stored candle are unknown, not missing: a symbol listed an hour ago has no earlier rows). `missing`, `due`, `stale` are *absent* and trigger catch-up; `conflicted` and `unavailable` do not; a slot stored and unavailable is `conflicted` (ADR-0002 P-7). Window verdict `WINDOW_NO_GAPS` means only: no `missing` and no `stale` slot in the classified span. `due`, `conflicted` and `unavailable` slots may exist and are shown by their own counts. `all_present` is reported next to it: true iff every classified slot is `present` (`present == slots_classified`, which is `classify_span_at`'s `fully_present`), so it is false whenever `due`, `conflicted` or `unavailable` is above 0. Both statements are about the classified span `[max(ws, oldest), T]` only: neither says anything about slots before the oldest stored candle or older than the window, and neither is worded as complete or as full coverage. The name `WINDOW_NO_GAPS` replaces the earlier `WINDOW_COMPLETE`, which a reader could take for 100 % coverage while `due` slots were still unstored.
4. **History is read series-wide, from stored facts, at every start.** One aggregate over the primary key finds the holes between consecutive stored candles (`LAG(open_time_ms) OVER (ORDER BY open_time_ms)`): the raw hole slots, the part older than `ws`, the number of runs and the five largest runs; two counts of `unavailable_candles` rows that lie inside holes (all, and older than `ws`) are subtracted, because an unavailable slot is accounted for; a third count gives the series' conflicted slots. Result: `HistoryStatus.HOLES` (unaccounted hole slots > 0) or `CONTIGUOUS_FROM_OLDEST` (none), always with `unknown_before_ms = oldest stored open time`, and `UNKNOWN` when no candle is stored or nothing was read. A hole survives a catch-up that fills the newer window because the slots between the old and the new candles stay absent: the aggregate keeps seeing it at every later start, which closes the "forgotten gap" hole of the earlier draft without any new state. Cost (not measured): one index-only scan of each series at start; reported to S23.
5. **What S15 can and cannot recover, per slot.** Window absent slots are recoverable by the current request (first round). `needs_s16 = unreachable_tail + unaccounted hole slots older than ws`. Holes inside the window are counted in the window, not in `needs_s16`. Partial recovery is visible as numbers from two database reads (`absent_before`, `missing`+`due`+`stale` after, `history_holes` after); the output never uses the word "recovered".
6. **The label `history_complete` is never emitted.** The schema holds no evidence of when a series started at the exchange (no first-listing fact, no S20 universe), so "complete" cannot be proven, only "contiguous from the oldest stored candle". Any consumer-visible `history_complete` needs an ADR and the listing evidence.
7. **First round.** `run_collection_loop(..., first_round_wanted_from: Mapping[str, int] | None = None)`: keys are configured symbols; values are aligned valid open times (`ValueError`/`TypeError` otherwise, before any task starts). For a mapped symbol the loop computes the request size **on every attempt of round one** from `clock.wall_ms()` with `attempt_limit` (arithmetic 2, 5); unmapped symbols and later rounds use `config.limit`. `collect_symbol` gains `limit_for_attempt: Callable[[], int] | None = None` and builds each attempt's config with `dataclasses.replace(config, limit=limit_for_attempt())`. Cost accepted: a retry because the target is still pending re-requests the same rows (at most 6 times).
8. **Post-check.** `after_first_round: Callable[[RoundReport], Awaitable[None]] | None` is awaited once after `on_round` of round one, only if `stop` is not set and round one did not end fatally. The CLI closure reads at `as_of = report.started_wall_ms` with `T = report.target_open_ms` (a boundary that passes during a long round cannot create false lines and the test is deterministic), prints window and history, and on any `Exception` from its read prints `reconcile-after status=unverified error=<text>` to stderr and returns (collection is healthy; only the claim is withheld). Any other `Exception` from the hook is a `FatalLoopError` in the loop (S14 Decision 8).
9. **Pre-start order and refusals** (`_run_loop`): install SIGINT/SIGTERM handlers; read (`reconcile`) before `open_source` and before the writer opens, so a database problem fails before any network call (`ReconcileError(StorageError)` → exit 1; any exception of the blocking part, including domain `ValueError`, is wrapped); a stop during the read ends the run with exit 0 without a source call. In `main()`, before anything is opened, `steady_state_limit_needed(delay, tf) > args.limit` is a usage error (`parser.error`, exit 2: "needs --limit >= N"), because no round could ever reach the target. `fetch-once` has the same impossible configuration and is left unchanged (listed as F-11).
10. **Output and exit codes.** Gaps and holes remaining after the post-check do not change the exit code (like `GAVE_UP` in S14); the lines are the evidence. `clock_behind_stored` (`newest_stored + tf + publication_delay > as_of`) is a **flag**, not a status: the window is still classified from the stored facts (a slot below the newest stored candle without a candle is `missing` whatever the clock says), the request size still comes from `attempt_limit`, and the history aggregate still runs. When the span `[max(ws, oldest), T + tf)` is empty (stored data begins at or after the window end) the status is `WINDOW_NOT_ASSESSED`.
11. **Out of scope, recorded as limits:** see "Residual risks and the S15/S16 boundary" at the end.
12. **A1 diagnostic, from existing data only.** `collect_symbol` gets an optional `observe_forming: Callable[[int, int], None] | None`; for round one the loop passes a per-symbol wrapper of `observe_forming_slot: Callable[[str, int, int], None]`, called after every successful `fetch_once` with `(max open time over eligible + pending, clock.wall_ms())` and not called when no row came back. The CLI keeps the maximum `lead` (domain `clock_lead_slots`) and prints it in the post-check summary (`clock_lead_slots_max=<n|->`); if it is above `REACH_MARGIN_SLOTS` it also writes a warning to stderr (`warning: the server's forming slot was <n> slots ahead of the local clock (assumption A1 allows 2); first-round requests may have missed up to <n-2> of the oldest wanted slots`). It changes no behaviour, sets no clock and adds no request, no dependency and no public API. **Boundary:** it observes round one only and only after the fact; it does not prevent a miss (the post-check does the truthful reporting) and does not watch drift while running. Continuous clock health belongs to S17 (health and readiness); S15 does not pretend to provide it.
13. **Start-up cost of the history read: measure, do not guess.** The benchmark of Task 2 step 5 is the evidence; its acceptance criteria are proposals for the user to set (HARD STOP 2). C1: on the `target` profile (600 series x 105 120 rows, one year of 5m) the first-run total of `reconcile_blocking` is at most 60 s. C2: the linear projection to three years (600 x 315 360 rows) is at most 180 s. C3: every statement uses the primary key (no `SCAN candles`), the `LAG` aggregate has no sorter, and the rows visited equal the rows stored. If a criterion fails, the options are (a) accept the measured delay, (b) read the history after the loop has started (the window read stays pre-start and fail-closed; this changes D4 and needs approval), (c) bound the scan by a look-back (weakens the old-hole guarantee), (d) a derived cache or checkpoint table (needs an ADR, D1). No index, cache, table or bound is added before the numbers exist.

### Task 1: Pure arithmetic and series reconcile

**Files:** Create `domain/reconcile.py`, `tests/domain/test_reconcile.py`.

**Interfaces:**
- Consumes: `classify_span_at`, `ExpectationRule`, `GapRun` (`domain/timed_coverage.py`); `MIN_TIMESTAMP_MS`, `ensure_timestamp_ms` (`domain/timestamps.py`).
- Produces:
  - `REACH_MARGIN_SLOTS: Final = 2`.
  - `max_target_distance_slots(publication_delay_ms: int, timeframe_ms: int) -> int` = `ceil(delay/tf) + 1` (delay 0 → 1).
  - `steady_state_limit_needed(publication_delay_ms: int, timeframe_ms: int) -> int` = `max_target_distance_slots + 1 + REACH_MARGIN_SLOTS`.
  - `attempt_limit(*, now_ms: int, oldest_wanted_ms: int | None, timeframe_ms: int, default_limit: int, max_limit: int) -> int` (arithmetic 2; `None` → `default_limit`; misaligned or newer-than-`F(now)` `oldest_wanted_ms` → `ValueError`).
  - `clock_lead_slots(server_forming_open_ms: int, local_wall_ms: int, timeframe_ms: int) -> int` = `(server_forming_open_ms - align_down(local_wall_ms))/timeframe_ms` (may be negative; `server_forming_open_ms` must be aligned).

## Residual risks and the S15/S16 boundary

**S15 guarantees** (each pinned by a test): the start-up output separates the recent window from the series history; it never says history is complete; a hole between stored candles stays reported at every later start for as long as the rows are absent; the numbers of slots that the current request cannot reach (`needs_s16`) are exact at the read; the first-round request size follows the clock at each attempt; recovery is shown only by a second database read, and when that read fails the claim is withheld; a configuration no round can serve is refused before anything is opened; a failed pre-start read stops before any network call; restarts converge and repeat starts write nothing.

**S15 does not guarantee, and no output may imply:**
1. That history before the oldest stored candle exists or does not exist (no listing evidence in the schema). Owner: a future ADR with S20.
2. Recovery of anything older than 997 slots before the forming candle, or of slots the exchange no longer serves. Owner: S16 (paging, `unavailable_candles`).
3. Detection of new gaps while the process runs; only the next start sees them. Owner: S16.
4. A hole whose slots were *deleted*: candles are immutable by trigger (ADR-0002 P-4) but a person with file access can remove rows; the aggregate would then report them as holes, which is the safe direction.
5. Assumption A1 (server forming slot at most 2 slots ahead of the local clock) is an operating assumption; it is diagnosed in round one after the fact (D12) and not watched afterwards (S17). The reading "the newest returned row is the forming candle" is observed (ADR-0001), not proven. A violation costs reach (reported as `still_missing` or as a history hole), never a false claim.
6. Cost: the hole aggregate scans each series' primary key at start. One scratch indication exists (34 s extrapolated, in memory), no benchmark result yet: **HARD STOP 2** (D13). A 1000-row request has a Binance weight that was not read; the limiter spacing is the only protection (S14 F-8).
7. The in-process write-uncertainty flag (F-8) is unchanged; a restart still cannot identify the uncertain batch, it only shows the stored state.

**Hard stops:** (1) Task 0, D1: nothing is implemented before the user answers it. (2) D13, the start-up cost: implementation may proceed, production use against a long history may not, until the user has accepted the benchmark numbers or chosen another option.
