> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Redraw `tools/symbol_overview/page.html` as a dark dashboard (mockup variant A, close to the user's screenshot) that answers: how many symbols we track, how many are healthy, how many miss something and what, which symbols those are, which are healthy.

**Architecture:** Only `page.html` (markup, CSS, script) changes, plus the tests that pin its markup and new pure functions (above the `// --- DOM below ---` marker, run under Node by pytest). One pure function, `dashboardModel(data, filter)`, turns the JSON into everything the page draws; the DOM part is a thin writer of that model. The page still draws exactly what `/overview.json` says and decides no state; every existing decision function keeps its meaning. The layout exists from the first paint (placeholders of final size), so loading never moves anything.

**Tech Stack:** plain HTML/CSS/JS in one file (no framework, no external request), Python 3.12 stdlib server (unchanged), pytest with Node.js (v16.13 here) for the page logic, ruff, mypy.

**Spec:** none written; the design was agreed in chat on 2026-11-06 and is in "Design" below. The older design documents of the page stay valid for data and states: `docs/superpowers/specs/2026-11-01-symbol-overview-design.md`, `2026-11-03-oi-6-open-interest-overview-design.md`, `2026-11-04-fr-6-funding-overview-design.md`.

## Design (agreed with the user, plus my calls marked "my call")

- Variant **A** of the mockup, **English** text, dark look like the screenshot (dark only; the light variant goes: my call). Icons are the glyphs of the mockup (`◈ ✓ ! ✕` in tinted circles), no SVG, no external file: my call.
- Top to bottom: header (title, subtitle, "last update" line, Refresh button) → `api-error` box → slim verdict banner (`headline()`, kept: it is the verdict of the page) → four tiles **Symbols / Healthy / Warning / Critical** (count and share) → three cards: **Symbol health** (donut + legend), **Healthy symbols by data** (Candles, Open interest, Funding rate: share of symbols whose state in that part is `ok`), **What is wrong** ("symbols per cause": one row per part and state; clickable = the old tile filter; one symbol can be in several rows, so the rows are not summed) → card **Needs attention (n)** with the symbol filter box → card **Healthy (n)** → card **Notes** at the very bottom (open interest / funding notices, the funding health line, refresh notices; they are the only variable-height content, so they sit below everything else).
- **Needs attention** and **Healthy** are plain lists of names separated by commas, sorted by name inside the Healthy list and in the existing `problemSymbols` order (worst first) in the other. Each name is a link; the detail page is **not** built (the link only changes the hash). Needs-attention names are colored by loudness (warn/bad); their `title` is the reason lines (`reasonLines`); a healthy name's `title` is its `unrecoverable` note when it has one (`okEntries`). Every link also has an `aria-label` (name plus worst state, e.g. `ETH/USDT: conflict`). Nothing is truncated.
- **A row is a series** (`venue`, `symbol`, `timeframe`; the API guarantees that triple is unique, and the tool turns any series other than `binance-usdm`/`5m` into an `unknown` row). Counts count rows. When the same `symbol` occurs in more than one row, every such row is shown as `SYMBOL (venue, timeframe)` in both lists and in tooltips. The link is `#/symbol/<encodeURIComponent(symbol)>?venue=<enc>&timeframe=<enc>` for every row (stable key for the future detail page; `encodeURIComponent` failing on a lone surrogate falls back to `#`).
- Warning / Critical = the existing `levelOf(worstState(...))` rule: `holes`, `behind`, `unverified`, `partly_verified` are warning, every other non-ok state (`no_data`, `unknown`, `stale`, `conflict`, `quiet`) is critical. The Critical tile carries a `title`: "includes 'cannot judge' and 'no data': the API cannot say more" (it must not claim more than the API says). Healthy = every part that applies is `ok`. No new rule.
- **Removed from the page** (belongs to the future detail page, still in the JSON and in git history): 30-day strips, heatmap, strip legend, the per-symbol funding line, per-state tile rows, the problems table.
- **Loading / error:** the static HTML already holds every card with placeholder blocks of the final size (`.skel`, shimmer), a banner placeholder, and `<body data-phase="loading">`. First successful render sets `ready`; any failure (page-level `api_error`, a network error, a timeout of 90 s, a throw inside render) sets `error`: values show `–`, no shimmer, `lastData` is `null` (so typing, `Esc` or a cause-row click cannot resurrect old data), the red `api-error` box says why. A later refresh keeps the old data on screen until the new answer renders (as today). `<noscript>` says the page needs JavaScript. Fail closed is unchanged: nothing is drawn healthy without an answer.

## Review Focus

Each line is pinned by a test in the task named.

1. A single problem symbol among thousands must not read "100.0 %" healthy or leave a pure-green donut; a non-zero count must not read "0.0 %" — Task 1 (`percentText`, `donutBackground`).
2. A symbol with no open interest / funding block while that part applies is Critical (`unknown`), never Healthy — Task 1.
3. Part disabled/absent: no percentage, no cause rows, a note saying which of the two it is — Task 1.
4. Zero symbols: counts `0`, shares `–`, neutral donut, the existing banner "no symbols"; nothing green — Task 1 and Task 2.
5. Names with `/`, `&`, `#`, spaces, quotes or a lone surrogate cannot break the link or inject markup — Task 1 (`symbolHref`), Task 2 (`textContent` only, no `innerHTML`).
6. A page-level error after a successful render leaves no old number, list or green donut, and no interaction brings them back — Task 2 (`lastData = null`, phase `error`).
7. The same `symbol` in two series (one ok, one `unknown`) is two distinct, distinguishable rows and tiles, banner and lists agree — Task 1 (`dashboardModel`).
8. A state string the page does not know is counted as Critical and still gets a cause row — Task 1 (`causeRows`).
9. A hung request ends in the `error` phase instead of shimmering forever — Task 2.

  - `healthCounts(symbols, status, fstatus) -> {total, ok, warn, bad}`; a row's loudness is `levelOf(worstState(s, status, fstatus))`; `ok + warn + bad === total`.
  - `percentText(n, total) -> string`: `"–"` when `total === 0`; `"0.0 %"` only when `n === 0`; `"100.0 %"` only when `n === total`; otherwise `(Math.round(n / total * 1000) / 10).toFixed(1)` clamped into `[0.1, 99.9]`, then `" %"`.
  - `partCoverage(symbols, status, fstatus) -> [{part, active, ok, total, note}]` for `"candles"`, `"openInterest"`, `"funding"` in that order. `active` is `true` for candles always, else `applies(status|fstatus)`. Active: `total = symbols.length`, `ok` = rows whose `partState` is `"ok"` (a missing block is `unknown`), `note = null`. Not active: `ok = 0`, `total = 0`, `note` = `TEXT.oiDisabled`/`TEXT.oiAbsent` (open interest) or `TEXT.fundingDisabled`/`TEXT.fundingAbsent` (funding) by status (`disabled` vs `absent`).
  - `causeRows(symbols, status, fstatus) -> [{part, state, count, level}]`: for every part that applies, count rows by `partState` for every non-`ok` state **actually observed**; states of the part's known list (`ORDER` for candles and open interest, `FUNDING_ORDER` for funding) and any other string (including `undefined`, reported as state `"unrecognised"`) get a row; `count > 0` only; `level = levelOf(state)`; sorted by `rank(state)` ascending (unknown strings first: `rank` is -1, they are the worst), then `count` descending, then part order.
  - `symbolHref(symbol, venue, timeframe) -> "#/symbol/" + enc(symbol) + "?venue=" + enc(venue) + "&timeframe=" + enc(timeframe)` with `enc = encodeURIComponent` wrapped in `try`; on a throw the result is `"#"`. `venue`/`timeframe` default to `""`.
  - `donutBackground(counts) -> string`: for `total === 0`: `"conic-gradient(var(--track) 0 100%)"`. Otherwise widths `w = max(warn/total*100, warn > 0 ? 0.5 : 0)` and `b` likewise for `bad`; `A = 100 - w - b`; string `"conic-gradient(var(--ok) 0 A%, var(--warn) A% B%, var(--bad) B% 100%)"` with `B = A + w`; numbers rounded to 2 decimals and printed as JS prints them. So a non-zero warn or bad is never narrower than 0.5 % and the ring is never pure green while a problem exists.
  - `dashboardModel(data, filter) -> {empty, counts, shares, donut, coverage, causes, attention, healthy, attentionTotal, healthyTotal, attentionLabel, healthyLabel, notes}`. `data` is a successful overview object; `filter` is `{query, part, state}`. Steps: `status = oiStatus(data)`, `fstatus = fundingStatus(data)`; `counts`, `shares = {ok, warn, bad}` as `percentText`, `donut`, `coverage`, `causes` over **all** rows (never filtered); `attention` = `problemSymbols(...)` filtered by `matchesFilter`, `healthy` = `okEntries` of the filtered rows sorted by label (`localeCompare`); each entry `{label, href, level?, title, aria}`: `label` = `symbol`, or `symbol (venue, timeframe)` when more than one row of `data.symbols` has that `symbol` (collision is decided over all rows, not over the filtered ones); `title` = reason lines joined by `"\n"` (attention) or the note (healthy); `aria` = `label + ": " + TEXT.states[worstState]`; `level = levelOf(worstState)` for attention. `attentionTotal`/`healthyTotal` are the unfiltered counts; `attentionLabel`/`healthyLabel` are `"n"` or `"shown of all"` (`TEXT.search.count`) when the filter hides rows; `healthyLabel` is shown beside `okGroupLabel(status, fstatus)`. `empty = data.symbols.length === 0`. `notes` = the non-empty strings of `oiNotice`, `fundingNotice`, `TEXT.fundingHealth(...)` (when the block has `health`) and `refreshNotices(data.refresh || {})`. The banner stays `headline(...)` computed by the DOM part as today.
