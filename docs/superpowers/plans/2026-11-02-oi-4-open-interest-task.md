# OI-4 Open Interest Task Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `quasar-collector run` collects 5m open interest continuously when the configuration has an enabled `[open_interest]` table: rounds on the derived cadence, restart reconcile, bounded catch-up of holes, isolation from candle collection and measurement (issue #4, ADR-0003 P-9, P-10, P-12, P-13, P-15 rows marked OI-4).

**Architecture:** Pure rules in `domain` (round schedule, hole derivation, page planning, try book). In `config`: the optional `[open_interest]` table. In `collector`: a read-only series reader, a measurement collector, one asyncio task (`open_interest_task.py`) that owns rounds, idle-window catch-up and the hourly measurement line, and three small hooks in the candle path (`CandleWriteActivity` entered around every candle write, plus the write duration). The task is started by `cli.run` after the candle loop's first round and post-check; it opens its own source (OI-3), writer (OI-2), budget and gate, and any exception ends only that task. Nothing in the candle loop waits for it.

**Tech Stack:** Python 3.12, asyncio, pytest, mypy strict, ruff, import-linter, `ManualTime` from `tests/collector/manual_time.py`.

**Spec:** `docs/adr/0003-open-interest.md` (P-9, P-10, P-12, P-13, P-15 OI-4 rows, P-16, amendment A-1), issue #4. Patterns: `collector/collection_loop.py` (`_WriteWatch`, `_sleep_or_stop`, idle window), `collector/backfill.py` (idle-window discipline, back-off in memory), `collector/hole_reader.py` (read-only snapshot per series), `collector/cli.py` (`_reconcile_and_collect`, `AsyncExitStack`, `_run_command`), `collector/fetch_open_interest_once.py` (parse, select, write), `collector/async_open_interest_writer.py`, `config/settings.py`, `domain/open_interest_cadence.py`, `domain/open_interest_request.py`, `tests/collector/open_interest_fakes.py`, `tests/collector/loop_fakes.py`, `tests/collector/test_open_interest_candle_contention.py`.

## Decisions this plan makes (not fixed by the ADR)

- **Round schedule is pure** (`domain/open_interest_schedule.py`). With `P = 5 min`, `wake(B) = B + round_offset_ms`, `deadline(B) = wake(B) + P − 15 s` (ADR: `B + 300 s + offset − 15 s`). `next_round(now_ms, last_boundary_ms, offset)` returns the boundary to run next, its wake time and how many boundaries were skipped: the newest boundary `B*` with `wake ≤ now` runs now if `now < deadline(B*)` and it is newer than the last run; otherwise `B* + P` (a future wake). Boundaries between the last run and the chosen one count as skipped. First round after start: same rule with `last = None` (skipped = 0), so a start inside a round's window runs that round late, a start in its last 15 s waits for the next.
- **Range of a round** `[B − 2c·P, B]` (`2c + 1` period ends), `as_of` = the round's `L` (see "Time"). Symbols come from `symbols_for_round` (OI-1).
- **Time (review 1: trust expires after 60 s):** `DEFAULT_TIME_TRUST.max_age_ms` is 60 000, so a bound re-evaluated at each request would turn untrusted in any round or window longer than a minute. Therefore `L = server_lower_bound(observation, now_ns, now_wall_ms, None, trust)` is computed **once, right after the observation**, and that one `L` is the `as_of_ms` and the eligibility bound (`TrustedTime(L)`) of **every request of that round or window**. This is safe: a lower bound stays a lower bound as time passes; it only makes eligibility more conservative. Exactly **one `fetch_server_time` per round that has symbols and one per idle window** (its `L` derives the holes, also when nothing is to be paged), so a cycle makes 2 time starts, the "Time ≤ 2" of P-10. There is no special call at task start: the first idle window (which always follows a round) makes its own, one per window, also when nothing is to be fetched. A failed or untrusted observation means **no request in that round or window** and one log line; there is no time retry. Rows are then fetched by the symbol's next overlapping request or the catch-up.
- **Per symbol in a round:** fetch → `parse_open_interest_hist` (OI-1) → `select_eligible_open_interest` (OI-1) → `writer.write(eligible)`. Symbols run with at most `MAX_IN_FLIGHT` (2) at once, each its own unit: one symbol's failure does not touch another's. **One retry** after a request error (`SourceError` that is not refused/paused/banned, `OpenInterestParseError`, a write failure) after a fixed 1 000 ms delay (the first step of the candle `RetryPolicy`, copied as a constant), only if the delay fits before the round deadline. `OpenInterestRequestRefused` is a bug, never retried, logged as error for that symbol. `OpenInterestPaused`: the round stops at once (`paused` outcome for the rest, log once), the task goes on to the next cycle. `OpenInterestBanned`: the task **ends** by raising (the cli prints the one `oi-error`; P-15 "418 stops the task").
- **Round deadline:** the round runs in a scope that is cancelled at `deadline(B)` on the injected monotonic clock. Symbols not finished are logged with their phase (`fetching` / `writing` / `waiting-for-candles`); rows still waiting for the candle writer are **dropped unwritten** and logged (P-9 rule 2); the next overlapping request stores them. Rounds are sequential in one task, so two rounds never run concurrently.
- **Catch-up runs only in idle windows** (after the round, until `next_wake − 15 s`; at start, before the first wake). It runs at most **one page at a time** (one request). **The whole window (its time call, reads and pages) runs in a scope cancelled at `idle_deadline`, like the round** (review 3a): a page hung in fetch, in `budget.acquire()` or in the writer's wait for candle writes can never delay the next round. The wall-clock `wake` is converted once per cycle to the monotonic instant `next_wake_ns = clock.monotonic_ns() + (wake_ms − clock.wall_ms()) × 1e6`, exactly as `collection_loop` computes `due_mono_ns`; the deadlines of the window and the round are compared on the monotonic clock only.
- **Backfill never starves a round (P-15 "rounds pre-empt backfill").** The ADR's share arithmetic is enforced by one rule instead of a scheduler: before starting a page the task asks the budget for `committed_at(next_wake)` (the counted starts whose 300 s window still covers the next round's wake instant, new method on `OpenInterestBudget`) and starts the page only if `committed + 1 + round_cost ≤ budget_per_5min`, where `round_cost = 2 × ceil(S / c) + 2`, **and** the start is grantable at once (`committed_at(now) + 1 ≤ budget_per_5min`; review 3b: `committed_at(next_wake)` is a subset of the starts counted now, so on its own it can pass while the budget is full and the page would then sleep in `acquire()` holding the budget's FIFO lock in front of the round). The same "grantable at once" test gates the window's own time call. Otherwise the window ends. Pure function `backfill_may_start(committed_now, committed_at_next_wake, budget, round_cost)` in the domain. **Implementation review 1:** `committed_at_next_wake` leaves out the previous round's own starts (`committed_at(wake, excluding=previous round span)`): they expire one by one while the next round makes its own, so counting both starved the catch-up at 149 to 600 symbols.
- **Hole derivation (P-12)**: with `L` = the window's server lower bound, `oldest = ceil_to_period(L − H)`, `newest = floor_to_period(L − expected_after_ms)` where `expected_after_ms = c × P + round_offset_ms` (P-10; slots newer than that are `not_yet_expected` and the rounds' overlap covers them; because `expected_after_ms ≥ 360 000 > MAX_PUBLICATION_DELAY_MS` every such slot is eligible). A hole is a slot in `[oldest, newest]` neither stored nor conflicted. Pages are built **per symbol**: greedily from the oldest available hole, a page extends to the last available hole within 500 period ends of its start (it may span stored or cooling slots). All pages of all symbols are ordered by `(start, symbol)`. The page request uses `as_of_ms = L` of its window (never a later bound), so a page that was valid when planned cannot be refused for age.
- **Re-derivation at the start of every idle window (ADR P-12, no deviation; review 5):** stored rows are immutable (INV-073), so a slot can only stop being a hole, and new holes can only appear at the newest edge. The task keeps the hole set per series. Each window: (a) a series **with holes** is re-read in full (`[oldest, newest]`, stored and conflicted) at the window start, so a hole filled by a round is never requested, and again after each of its own pages; (b) a series **without holes** is read only for the stretch that became expected since the previous window, `[previous_newest + P, newest]`, and its unstored slots join the hole set. Both are exact derivations from the stored rows; no hourly rescan and no discovery delay. Reads run one series at a time, each in its own short read transaction on `asyncio.to_thread` (the same pattern as `hole_reader.py`; this is the interpretation of the P-9 table's "open interest thread": reads are off the candle writer's thread, which is the purpose). A failing read raises `OpenInterestReadError` and **stops the task** (P-12 point 1).
- **Tries (P-12 "Holes Binance does not serve")**: `OpenInterestTryBook` in `domain/open_interest_tries.py`, in memory only, kept as runs of consecutive slots per symbol with `(tries, next_allowed_ms)`. A slot is **tried** when a page covering it as an *available* slot (cooldown expired, fewer than 3 tries) succeeded (valid response, all transactions committed), the slot is **absent from the parsed response** (any returned row for it, eligible or not, means Binance served it), and the page's selection has **no pending row and no `untrusted_reason`** (otherwise the page records no tries at all: a row Binance did serve but we could not yet judge must never use up a try; review 2). Cooldown after try 1: 1 h, after try 2: 6 h, after try 3: never again in this run. Cooling slots inside a page are fetched and stored if present but their count and cooldown do not change. Errors are not tries.
- **Unusable writer (review 9):** a write failure whose cause (`OpenInterestPageError.cause`, or the error itself) is an `OpenInterestWriteError` that is neither `OpenInterestWriteBusy` nor `OpenInterestWriteOutcomeUnknown` (a writer closed after a failed rollback, a SQL error, a closed state) **ends the task** with an `oi-error` (raised as `OpenInterestWriterUnusable`, a new exception in the task module); retrying every round and suspending every symbol would be a silent degraded state. Busy and unknown outcome are the retryable kinds.
- **Page errors:** per symbol `failures`; after the n-th consecutive failed page the symbol waits `2^(n−1)` cycles (1, 2, 4), the 4th consecutive failure suspends that symbol's catch-up until restart; a successful page resets the count. Logged on each step. A `429` (`OpenInterestPaused`) ends the window and is not a failure; `OpenInterestRequestRefused` counts as a failure.
- **Urgency warning (P-12):** at the start of each window that has pages, for non-exhausted holes with `T < L − H + 1 day`, the plan is replayed; a hole whose page position exceeds `cycles_left(T) × backfill_share(S, b)` requests (cycles_left = `(T − (L − H)) // P`) is "will be lost"; one `oi-warning` line per series names the count and the first 5 slots. Also a per-window line with the number of slots at 3 tries per series.
- **No-longer-recoverable in the reconcile summary (exact, review 10):** at start the reader also returns the series' first stored `time_ms` (`MIN`) and the number of stored rows older than `oldest` (`COUNT(*) WHERE time_ms < :oldest`, one range count, start only). The count is `(oldest − first_stored) / P − stored_older` slots between the first stored row and the horizon that are not stored, `0` for a series with nothing older. Slots before the first-ever stored row are not counted (the start of the history is unknown); the README says so.
- **Start gate:** the task is created at run start and waits on an `asyncio.Event` set in a `finally` at the end of the first-round post-check (so also after a post-check error), and never set when the first round is fatal. It opens its source (loads markets: network) and writer only after that.
- **Measurement (P-9 rule 5):** `OpenInterestMeasurements` collects yields, yield wait, OI transaction durations, busy count (a write failure whose cause is `OpenInterestWriteBusy`) and candle write durations (reported by the candle path hook). A-1 asks for the p99 of a **100-row** transaction, so transaction durations are kept twice: all transactions, and those with exactly 100 rows (transaction `i` of a page of `n` rows has `min(100, n − 100·i)` rows, from the chunking in `AsyncOpenInterestWriter.write`). The partial report of an `OpenInterestPageError` is recorded too; every `3 600 s` of monotonic time the task prints one `oi-measurement` line (count, p50, p99, max by nearest rank) and resets, plus a last line on a clean stop if anything was collected.
- **Output:** one injected callable `emit(line)`; `cli` writes lines whose first token starts `oi-warning` or `oi-error` to stderr, the others to stdout. Line families: `oi-reconcile`, `oi-round`, `oi-conflict`, `oi-catchup`, `oi-warning`, `oi-error`, `oi-measurement`.
- **Factory seam changes (test seam):** `OpenInterestOpenSource` becomes `Callable[[OpenInterestBudget, OpenInterestGate, Clock], Awaitable[OpenInterestOnceSource]]`, default `BinanceUsdmOpenInterestSource.open`; `fetch-oi-once` builds budget (`DEFAULT_BUDGET_PER_5MIN`) and gate itself, `run` builds them from the config. `open_binance_open_interest_source` is deleted.
- **P-15 wording:** the row "open interest leaves no half-written page (atomic per page)" is read with P-9 rule 1: every *transaction* is atomic; a page of more than 100 rows may stop between transactions and the next try completes it. The test asserts exactly that (stored rows after a cancel are whole transactions; a second run adds the rest with no duplicate or conflict). Reported to the user as a wording clarification.
- **API half of "Collector and API derive the same `c`":** the API does not read `[open_interest]` before OI-5. OI-4 proves the Collector side from `Settings` for b = 100, 200, 400 using the shared domain function; OI-5 adds the API half.
- **No new dependency, no new abstraction** beyond the modules named in the tasks.

## Review Focus

1. Pure schedule and planner properties: `next_round` against a brute-force model; page plan determinism, order, ≤ 500 period ends, nothing older than `L − H`, cooling/exhausted slots never planned (Tasks 2, 3).
2. The try book against a naive per-slot model (random operations); exact cooldown boundaries (Task 3).
3. Budget: no 5-minute window ever exceeds `b`, rounds-only windows never exceed `2 × ceil(S/c) + 2`, and a round request is granted while a backfill page waits (Tasks 4, 7, 8).
4. Isolation: hang, raise, 429 and ban of the OI source leave candle `RoundReport`s (results and `lateness_ms`) identical to the run without OI; disabled config creates nothing (Tasks 5, 8, 10).
5. Contention: candle write in flight ⇒ no OI `BEGIN` until it ends (recorded timeline through the real loop hook); yield until the deadline drops rows and the next request stores them (Tasks 5, 7, 10).
6. Restart: a stop at any point leaves whole transactions only; a second start converges and adds nothing; unknown outcome then restart adds no duplicate/conflict (Tasks 8, 10).
