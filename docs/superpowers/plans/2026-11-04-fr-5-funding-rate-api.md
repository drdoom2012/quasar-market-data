## Decisions (implementation; contract decisions are FA1 to FA10)

1. **A-3 is a replacement, not a second class.** `ExtensionPause` already has the semantics, attributes (`generation`, `paused()`, `check()`, `record_rate_limited`, `record_success`, `record_banned`) and exception shapes (`remaining_ms`, `until_monotonic_ns`) of `OpenInterestGate`. Every use of the gate is renamed; `open_interest_gate.py`, its pyproject entries and its test file go; the gate's tests are covered by the existing `ExtensionPause` tests (verified in Task 1 before deleting: every gate test has a counterpart; any that has none is moved). No alias. `binance_usdm_open_interest.__all__` re-exports `ExtensionPaused` / `ExtensionStopped` (the pattern of `binance_usdm_funding_rate.py`), and tests import them from `extension_pause`. `run` creates **one** `ExtensionPause` and gives it to both datasets when both are enabled; `fetch-oi-once` creates its own. Each dataset keeps its own limiter/budget (ADR-0004 P-9: no shared bucket). **Observable changes of A-3 (all listed in the amendment and the PR; review 2026-11-04):** the `oi-error task stopped: <Class>: <message>` line now names `ExtensionStopped` and its message, the ban log line and logger name are the pause's; the OI warnings `Binance answered 429` / `time request answered 429` are reworded to `paused (429 seen by an extension dataset)` because they now also fire when funding set the pause and OI sent nothing; the doubling counter is shared (an OI 429 right after a funding 429 with no success in between pauses 600 s). With funding disabled nothing else changes.
2. **Import contracts.** OI modules may import `extension_pause` (the OI contract forbids only the candle limiter and shared server time). The funding contract already lists `extension_pause` as a source module forbidden to import OI modules: unchanged. The negative case `open_interest_gate_importing_the_candle_rate_limiter_...` is **deleted** (the gate module no longer exists; the case for `binance_usdm_open_interest` importing `rate_limiter` already exists) and `extension_pause_importing_the_open_interest_gate_...` is retargeted at `open_interest_task`. To give "each keeps its own limiter" a named negative test, the OI independence contract also forbids `funding_rate_limiter`, `binance_usdm_funding_rate` and `funding_rate_task` (with a failing case), and a positive case shows an OI module importing `extension_pause` passes. Candle modules still must not import `extension_pause` (unchanged).
3. **The window is the closed interval `[start, end]`** and times are not aligned (FA1). `params._timestamp` demands alignment, so a new `_instant(name, text)` (range check only, `end` maximum is `MAX_TIMESTAMP_MS`, not `+ timeframe`) is used. Funding has no `timeframe` / `period` parameter, so it gets its own `_funding_series_and_start` (venue, symbol rules shared with `_series_and_start` through a small extracted helper, no label) and `_limit` takes a minimum (2 here, 1 elsewhere) with its own message. `end < start` is `400`; `end == start` is valid.
4. **Window cap** `MAX_FUNDING_WINDOW_MS = 3650 * DAY_MS` (FA2) is checked on the **effective** window. For an explicit `end` it is a parameter check (`400`, `details.maximum = 315360000000`, unit ms, message names days). For a defaulted `end` the handler computes `min(max(as_of_ms, start), start + MAX_FUNDING_WINDOW_MS)` after reading the clock and echoes it (the user chose the candle-style cap on 2026-11-04; contract 6.7.2 and FA2 amended). No `400` depends on the clock, so the order of checks of 6.7.6 is unchanged.
5. **Paging (FA3).** The reader reads `limit + 1` rows ordered by the primary key `(funding_time_ms, rate_type)`. If the row at index `limit` has the same `funding_time_ms` as the row at index `limit - 1`, the page is `rows[:limit - 1]` (never fewer than one row because at most two rows share a millisecond and `limit >= 2`), else `rows[:limit]`. `next` is `rows[len(page)].funding_time_ms` or `None`.
6. **Series existence (FA4).** Unknown only when there is no `funding_rate_verified` row **and** no `funding_rates` row. `series.*` are row-only (`null` / `null` without a row).
7. **Coverage in the same snapshot.** One `BEGIN`; statements: schema check, span row, MIN/MAX (two scalar subqueries), rows (`LIMIT limit + 1`), per-row conflict keys within `[first, last]` of the page, `COUNT(*)` of rows in the window, `COUNT(*)` of `DISTINCT (funding_time_ms, rate_type)` conflicts in the window. A constant number of statements; `EXPLAIN QUERY PLAN` tests assert `SEARCH` on the primary key and `SEARCH` on **either** conflict index (`funding_rate_conflicts_event` or the covering `funding_rate_conflicts_observation`; the planner may choose), never `SCAN`. SQLite has no `COUNT(DISTINCT a, b)`: the conflict count is `SELECT COUNT(*) FROM (SELECT DISTINCT funding_time_ms, rate_type FROM funding_rate_conflicts WHERE ...)`.
8. **Health uses the Collector's functions.** `behind` = `is_behind(as_of_ms - publication_delay_ms, span)`; `catching_up` = `history_pending(span, backfill_days)`; `quiet` = no row or `as_of_ms - newest > 172_800_000` (strict). One pure function `funding_series_health(...)` in `domain/funding_rate_coverage.py` returns the three flags; the app only counts. `recheck_ms` is validated by `load_settings` (the API refuses to start on a bad value) but not used by the API: nothing in 6.7 needs it; contract 6.7.7 is **not** edited.
9. **Health reader.** `read_ingest_snapshot` and `read_ingest_open_interest` keep their signatures. A new `read_ingest_extensions(db_path, *, oi_conflicts_after_ms: int | None, funding_conflicts_after_ms: int, ...) -> IngestSnapshot(candles, open_interest: OpenInterestFacts | None, funding_rate: FundingRateFacts)` runs in one snapshot; the handler uses it only when funding is enabled, otherwise the existing branches run untouched (zero change for deployments without funding). Per funding series: one next-series seek on `funding_rate_verified` (PK), one `MAX(funding_time_ms)` seek on `funding_rates` (PK), one `LIMIT 1` probe of `funding_rate_conflicts_event` (`funding_time_ms > ?`): O(series).
10. **Key position.** `funding_rate` is the last key of the `/health/ingest` body, after `open_interest` (contract 6.2.3).
11. **No Collector change for FR-5**, no schema change. Tests insert funding rows with plain SQL via `tests/api/seed.py` helpers (as for candles / OI; some rows seeded a few ms after the hour, not only on whole hours), plus one end-to-end test through the real `funding_rate_writer` (conflict labels agree).
