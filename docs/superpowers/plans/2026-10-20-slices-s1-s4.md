# Market Data v1 — Slices S1–S4 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a boundary-enforced project skeleton (S1), a Binance fidelity/time spike with a draft ADR-0001 (S2), the pure `Timeframe` / decimal-text / `Candle` domain core (S3) and fail-closed candle validation (S4).

**Architecture:** `src/quasar_market_data/{domain,collector,api}`. `domain` is pure (stdlib allowlist only, no I/O, no wall clock); `collector` and `api` are mutually independent. Boundaries are enforced by `import-linter` plus an AST allowlist test (their capabilities differ; see Task 2). S2 is the only slice that touches an exchange; its fixtures and ADR feed S3–S4.

**Tech Stack:** Python 3.12, uv, pytest, ruff, mypy (strict), import-linter. CCXT only in a `spike` dependency group (S2). No FastAPI, TA-Lib or sqlite code in S1–S4.

**Spec:** `docs/superpowers/specs/2026-10-20-market-data-v1-design.md` (also `CLAUDE.md`, `docs/architecture.md`)

## Global Constraints

- Priority order: Correctness → Data Integrity → Reliability → Simplicity → Performance.
- Python 3.12; tools: uv, pytest, ruff, mypy, `import-linter` (only extra dev dependency). Commit `uv.lock`.
- First venue/market: Binance USDT-M perpetuals; timeframe 5m; v1 dataset is OHLCV only.
- Schema is independent; no compatibility target with any prior contract.
- `turnover` only when the venue provides it, otherwise `None`/`NULL`; never computed, estimated or derived.
- Canonical OHLCV and `turnover` come from the CCXT implicit raw endpoint; unified `fetch_ohlcv` is used only for comparison in the S2 spike.
- Canonical numbers are decimal text; never float; never assume float→`Decimal` restores precision.

- Standard tests never use live exchanges; the `live` marker is excluded by default. Spike scripts hit the network only when run by hand.
- Tests never touch production storage.
- Candle **construction** enforces structure only; **content validation** is `require_valid()`. No candle may reach persistence without passing `require_valid()` (obligation for S7: the writer accepts only `ValidatedCandle`, with a test that an invalid candle is not persisted).

## Decision register

Three kinds of statements are kept apart. Only S2 produces measured results; none exist yet.

### Decided (given by the user; not re-opened by this plan)

| ID | Decision |
|---|---|
| D-A | Canonical OHLCV and `turnover` come from the CCXT implicit raw endpoint. Unified `fetch_ohlcv` is used in the spike only for comparison. Both spike requests must be verified to target the same Binance USDT-M market, instrument and fixed time range; matching timestamps alone is not sufficient. |
| D-B | Intended meaning of `turnover`: actual traded volume in the quote currency for the interval. S2 verifies in the official Binance documentation the meaning of raw index 7 and the unit of index 5 for USDT-M contracts; if they match, index 7 maps directly to `turnover`. `turnover` is never derived by computation. The `turnover/volume ∈ [low, high]` check is only a supplementary sanity check. |
| D-C | Publication delay: 5 s as a configurable initial value. |
| D-D | Eligibility uses a conservative lower bound of server time: `open_time + timeframe + publication_delay <= server_time_lower_bound`. Offset is measured with local time before/after a server-time request; RTT and an uncertainty estimate are recorded and kept separate from the offset. Limits on RTT, measurement age and uncertainty are configurable and justified in ADR-0001. Untrusted time ⇒ no new candle is confirmed, re-synchronize, report a degraded state. (Refinement: RTT, age and elapsed time are computed from monotonic clocks only; the wall-clock offset is diagnostic and kept separate from the monotonic computation.) |
| D-E | A just-closed candle that is not yet available: retry and report coverage; never store the forming candle and never fabricate a substitute. |
| D-F | Recheck of the same fixed closed range after ≥ 1 h, compared by candle identity on canonical numeric values. Equality is partial evidence only. A difference never causes a silent overwrite; it feeds auditable conflict handling (S8). |
| D-G | Decimal text: explicit ASCII grammar, bounded exponent, limits on input length and on the size of the plain result, no rounding. Unexpected formats seen in S2 are investigated first; the grammar is not extended automatically to make a fixture pass. |
| D-H | `venue` identifies the exchange **and** market segment. `symbol` is stored in an explicitly chosen format; the `market_id` ↔ symbol mapping must be lossless. No narrow symbol regex built from BTC and one cheap instrument. A second exchange is verified in its own slice. |

## Review Focus

Inputs the spec implies but a straightforward test set would miss; each is pinned by a named test.

1. Integer-valued decimals with trailing zeros (`"1000"`, `"1000.00"`, `"10"`) must keep their integer digits (Task 6).
2. Hostile numeric text — underscores, non-ASCII digits, trailing newline, huge exponents, over-long mantissas — is rejected before any expansion, and every accepted value re-canonicalizes to itself (Task 6).
3. `bool`, `float`, `int` subclasses, out-of-range, misaligned (in-range) and end-overflowing timestamps are rejected at every entry point (Task 5, Task 7).
4. Off-by-one between Binance `closeTime` (inclusive, ms) and the exclusive boundary `open_time + timeframe` (Task 4 analysis, Task 5 `end_exclusive_ms`, Task 9).
5. Price comparisons stay exact for values with more than 28 significant digits (Task 8).

### Task 4: Analysis and draft ADR-0001

**Files:**
- Create: `spikes/analyze_binance.py` (throwaway)
- Create: `docs/adr/0001-binance-ingestion-fidelity-and-closed-candles.md`

**Analysis procedure (the script prints; the ADR records results, sample sizes and dates):**

1. **Identity, market and completeness.** Pair unified and raw rows by `open_time`; check equal sets, contiguity, interval. Verify both requests address the same USDT-M market (Task 3 test) **and** that paired numeric values agree to float-representable precision; a pair that diverges beyond that points to a different market or range and is investigated before any other conclusion.
2. **Numeric loss (comparison only).** For each paired row and each of open, high, low, close, volume: compare `Decimal(raw)` with `Decimal(str(unified_value))`. Report *numeric differences* (precision loss) separately from *formatting-only differences* (equal value, different text).
3. **Observed text forms.** From all raw numeric strings: exponent, leading `+`, leading zeros, maximum digit count and length. Strings outside the Task 6 grammar or limits are **investigated and listed**; the grammar is not extended merely so the fixtures pass, and any change goes through an ADR-0001 amendment approved by the user.
4. **Time semantics.** `closeTime` vs the exclusive boundary `open_time + 300_000` (hypothesis: `closeTime == boundary - 1`); forming candle identified by `closeTime >= server_time`. For every `time_observation` compute, keeping the two clock families apart:
   - **Monotonic (used for eligibility):** `rtt_ms = (monotonic_after_ns - monotonic_before_ns) / 1e6`; `uncertainty_ms = rtt_ms` (the true server reading lies within the request interval, so the bound's width is the RTT); between two observations `i`, `j`: `server_elapsed_ms = S_j - S_i` vs `local_elapsed_ms = (monotonic_after_ns_j - monotonic_after_ns_i) / 1e6`, giving an observed rate difference in ppm with its error bound `(rtt_i + rtt_j) / local_elapsed_ms`; check that `S_j >= S_i` (W-6).
   - **Wall clock (diagnostic only):** `offset_estimate_ms = server_time_ms - (wall_before_ms + wall_after_ms) / 2`, reported as its own quantity and never combined with `rtt_ms`; the divergence between wall and monotonic elapsed time between observations, as input for the divergence-check threshold.
   Report the distributions of RTT, offset estimate, rate difference and divergence across all captures, including captures ≥ 1 h apart.

**ADR-0001 structure — three explicitly labeled parts:** **Decisions** (given by the user: items D-A … D-H in the register above, quoted as such), **Proposals** (derived from evidence, awaiting approval), **Evidence** (measured results with sample sizes and dates; nothing from the register is presented as measured).

**ADR-0001 must record:** (a) decimal source — raw implicit endpoint canonical, unified for comparison, and the sample's limits (**absence of differences in a sample is not evidence of general float losslessness**; persisting from raw strings rests on exactness by construction); (b) kline field mapping (indices 0–11), the documented meaning of indices 5 and 7, and the `turnover` mapping decision; (c) the closed-candle eligibility rule: Binance `closeTime` vs the exclusive boundary; equality at the boundary; the publication delay (initial value 5 s, configurable); the **server-time lower bound**, defined entirely on monotonic time. For an observation with monotonic send time `m0`, monotonic receive time `m1` and server reading `S` (milliseconds), at later monotonic time `m_now`: `age = m_now - m1`, `server_lower_bound(m_now) = S + age * (1 - max_drift_ppm / 1e6) - precision_margin_ms`, and a candle is eligible iff `open_time + timeframe + publication_delay <= server_lower_bound(m_now)`. The ADR states the assumptions explicitly: (A1) `S` is the server clock reading at some instant between `m0` and `m1`, so the true server time at `m1` is at least `S` (no deduction is needed for millisecond truncation); (A2) the local monotonic clock does not jump; (A3) the relative rate error is at most `max_drift_ppm` (W-5), which is what the **drift reserve** covers; (A4) `precision_margin_ms >= 0` covers the clock resolution and any measurement error not otherwise modeled (W-6 is checked separately). `max_drift_ppm` and `precision_margin_ms` are configurable and their values are justified by the measured distributions. **Conditions for rejecting an observation (time untrusted):** no observation yet or the request failed; `rtt_ms > max_rtt_ms`; `age > max_age_ms`; `uncertainty_ms > max_uncertainty_ms`; `S` smaller than the previous accepted observation's `S` (server time regressed); or the wall-clock/monotonic divergence check fails — the absolute difference between wall elapsed and monotonic elapsed since the observation exceeds `max_clock_divergence_ms` (this catches system suspend or a wall-clock step; it is a **rejection gate only** and never enters the lower-bound computation). While untrusted: no new candle is confirmed, re-synchronization is retried with bounded backoff, and a degraded state is reported; already stored candles are unaffected. The wall-clock offset estimate is reported for diagnosis only. All `max_*` limits are configurable and justified by the measured distributions; (d) a missing just-closed candle: retry, report coverage, never store the forming candle or any substitute; (e) temporal eligibility vs **any guarantee that the exchange will not change history later** — the latter is not established; later differences feed S8 conflict handling and are never silently overwritten; (f) the canonical decimal grammar/limits and the outcome of item 3; (g) venue naming convention (`<exchange>-<segment>`, identifying exchange and market segment), the explicitly chosen stored symbol format and the lossless `market_id` ↔ symbol mapping evidenced by the survey; (h) fallback if the implicit endpoint proves unusable: direct HTTP needs a new ADR.

### Task 6: Canonical decimal text

**Files:**
- Create: `src/quasar_market_data/domain/decimal_text.py`, `tests/domain/test_decimal_text.py`

**Interfaces:**
- Produces: `class InvalidDecimalError(ValueError)`; `canonical_decimal(value: str) -> str`; `to_decimal(canonical: str) -> Decimal`.
- **Accepted grammar (ASCII only, full match):** `[+-]?[0-9]+(\.[0-9]+)?([eE][+-]?[0-9]+)?`. Rejected by construction: underscores, whitespace (including a trailing newline), Unicode digits, `.5`, `5.`, `NaN`, `Infinity`, hex, empty.
- **Limits (decision D-G; the numeric values are working assumption W-2 until ADR-0001), defined so that the accepted set is closed under canonicalization.** Constants: `MAX_INPUT_LENGTH = 128`, `MAX_MANTISSA_DIGITS = 96`, `MAX_EXPONENT = 32`, `MAX_CANONICAL_DIGITS = 96`. An input is accepted iff all of the following hold:
  1. it matches the grammar and `len(value) <= MAX_INPUT_LENGTH` (checked first);
  2. its mantissa digits (integer + fraction, leading zeros included) number `<= MAX_MANTISSA_DIGITS` and `abs(exponent) <= MAX_EXPONENT` (both checked **before** any expansion, so work and memory are bounded by roughly 96 + 32 digits);
  3. its canonical result has `<= MAX_CANONICAL_DIGITS` digits in total (integer digits, including the single `"0"` of a pure fraction, plus fractional digits). Larger results are rejected with `InvalidDecimalError`; nothing is truncated or rounded.

  **Closure property (must hold and is tested):** every canonical output has at most 96 digits and at most 98 characters (digits, one point, one sign), so it satisfies conditions 1–3 and re-enters `canonical_decimal` and `to_decimal` unchanged: `canonical_decimal(canonical_decimal(x)) == canonical_decimal(x)` for every accepted `x`. Canonicalization never rounds.
- **Procedure (string arithmetic only; no `Decimal` arithmetic, no rounding, no context):** split sign / integer digits / fraction digits / exponent; shift the decimal point by the exponent by moving digits and padding zeros; strip leading zeros of the integer part (keep one digit); strip trailing zeros **only from the fractional part** and drop the point if the fraction becomes empty; an all-zero value becomes `"0"` (so `"-0"` → `"0"`); `+` is dropped; `-` is kept for non-zero values. Negative text is syntactically valid here — sign rules belong to validation (Task 8).
- `to_decimal(canonical)` accepts **only already-canonical text**: it raises `InvalidDecimalError` if `canonical_decimal(canonical) != canonical`, then returns `Decimal(canonical)`.
- `canonical_decimal` raises `TypeError` for non-`str` input (including `float`, `int`, `Decimal`, `None`).
